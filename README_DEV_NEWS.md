## 2026-11-01 — 国の動きをよりリアルに：景気・財政・雇用

2,000人の国で2年、5万人の国で数か月を動かし、現実の経済と比べておかしかった所を直した。
- **景気（企業側の `w.econ`）**：毎月「プレイヤーと市民のお金の増え方」そのもので押していたため、いつも増え続ける預金が景気をずっと押し上げた（記憶18か月で中心の1.3〜1.8倍）。**いつもより速いか遅いか**（増え方の約1年の平均からのずれ、±5%まで）で押すように（`WEALTH_TREND`）。
- **景気（市民側の `W.stats.economy`）**：直近30日の支出を1年と比べていたため、車の購入やボーナス月で1か月に1.1〜1.9と大きく揺れ、テネシスの金利と区長の支持率まで揺れた。**直近の四半期（90日）**で測る。
- **財政**：会社の税金で国庫が2年で約$5,000億までたまり続けた。議会は赤字のときだけでなく**黒字が続くとき**（国庫が下限の5倍超・収入が支出の1.1倍超）にも、公共事業・交付金の増額か消費税の引き下げを提案。さらに国庫のうち下限の5倍を超える分は約1年かけて公共事業に（均衡財政のルール）。
- **雇用**：失業者がいつも0%だった。① 求人への応募が2日ほどで決まっていた → 書類選考・面接の分、1日の内定の確率を `NPC.labor.offerDaily`（0.5%）に（失業期間は数か月）。② 会社員の離職が満足度の高い人で会社の離職率の1/5（年1%台）まで下がっていた → 下限を6割に（家庭・引っ越し・転職など自分の理由でも辞める）。③ 地元の仕事（その他・自営業・パート）は一度も終わらず、失業者は13社にしか雇われなかった → 地元の仕事も月1.5%で終わり（自営業はその35%、地元の商売の資金が足りないと2倍）、失業者は地元の仕事にも就く（`localJobs`）。2,000人の国で失業率は約1〜1.5%（日本は約2.5%）。
- 検証：`npc.test.js`（雇用の出入り・失業率）。

## 2026-11-01 — 国が動き出しても会社は国外にも売る（大幅な赤字と人員削減の連鎖を解消）

- **国が動き出すと多くの会社が毎日赤字だった**：国が動き出した日から、国内の会社の売上の式は止まり、市民5万人・プレイヤー・他社が払うお金だけが売上になっていた。費用は元の規模のままなので、テネシスは計画の1日+$0.44Bに対して−$0.37B（$450B/年の業務粗利益が1日約$60M）、カーオーナー・MAGITA・シティーワークなども赤字。最初の四半期末から計画の50%未満で人員削減が続いていた（2,000人の国で2年でテネシス−45%）。
- **国外の取引（`outside`）**：その流れの計画の1日分のうち、国内（市民・プレイヤー・他社、`s.pr`）から最近入っていない分を国外のお客さんが買う（掛け売り・入金は輸出として国に入る）。製品は製品ごとの国外の客数から、カーオーナーの国外向けの車は在庫ではなくメーカーから。平均は `s.po`、経営陣の見込み（`expectCountry`）にも入る。スタジオのゲーム（`gameScale`）・MY WAYのライセンス・YOSIDAの種・会社間の取引は対象外。テネシスは `bankCountry` で国外の業務（各流れの計画との差）とその与信費用。
- テネシスの「資金利益」の平均（`s.pr.nii`）が二重に減らされ実際の半分だったのを修正。役務取引等利益（`s.pr.fees`）も数える。
- **スタジオ（RIRU・ICE）も国外でゲームを売る**：国が動くとゲームは市民の購入だけになり、2年でICEの社員が半分に。各タイトルを販売曲線どおり・旧作も、国内で最近売れていない分だけ国外で（掛け売り・プラットフォーム手数料は国外へ、`po.game`）。スタジオの `s.pr.game`・`s.pr.live` も二重に減らされていたのを修正。2,000人の国の2年でICEは64→72人、物価は+4.6%。
- **採用計画の上限**：会議の「人員の増強（+5%）」と好業績の採用拡大が上限なく積み重なり、MY WAYは2年で規模の2.5倍（他社の社員を奪う）。採用計画は国の大きさでの規模の1.5倍まで（`targetCap`、減らすのは自由）。
- 結果（5万人の国・最初の四半期末）：テネシス 計画の94%（1日+$0.44B）、カーオーナー104%、MAGITA・ジンクスなども黒字。人員削減なし。お金の保存は毎日数ドルの丸め以内。
- 検証：`npc.test.js`（国が動いてからも主要4社が黒字・人員を減らさない・国外に売っている）。

## 2026-11-01 — 価格の見直し：売っているものは「少し高い」くらいに（ガチャ・車の買取・貸し出し・金の生る木）

価格を、手に入るものの売値・稼ぎと比べて全部確かめた（`server/test/prices.test.js`）。お金が増え続けた所を直した。
- **ガチャ**：景品を売った額の期待値が値段の1.45〜6倍だった（シークレットのリリース記念セールは約4.4倍）。「ランダムな車」を一様（12台に1台が$300MのMAGITA ONE白）から**価格の逆数の重み**に（`GACHA.randomCar`・`carPrice`、ガチャ限定のクイヤスパイダーGTは$24M）。車の確率を下げてリセットチケットへ：レア オンヴォーロ7→1.7%・GT 2→0.5%・ランダム1.985→0.485%・リセット15→23.3%、レジェンダリー オンヴォーロ5→3.5%・GT 4→2.8%・ランダム10.995→7.635%・リセット15→21.06%。シークレットはそのまま。リリース記念セールのシークレットは$10M→**$28M**。期待値は値段の約74〜81%、キャンペーン（車1.5倍）でも約93〜98%（セールと重なっても約100%まで）。
- **車の買取**：基準を「今の販売価格」から「今の販売価格と、買ったときに払った額の小さい方」に（`BR.sale.buyback` の `paid`）。セールで買ってセールのない日や大廃棄セールの日に売り戻すと最大+77%になっていた（ガレージは$1Mで何台でも増やせるので無限に増えた）。もらった車・払った額のない車は今までどおり。
- **車の貸し出し**：お客さん1人の支払いが車の価格の対数でしか増えず、$3.6Mの車は9日・$300Mの車は514日で元が取れていた。**車の価格の0.1%（±20%、VIPのお客さんは3倍）**に（`carRental.rate`・`spread`・`floor`・`vip.mult`、共通の `BR.sale.rentPay`）。どの車も約86〜89日で元が取れる（手数料・ガレージ代の前）。ガチャ限定車も自分の価格で。
- **金の生る木**：毎秒の生産を半分に（$5〜$14 → **$2.5〜$7**）。市場の木（$10〜21M）が15〜30日で元が取れていたのを約30〜60日、肥料は約30日に。

## 2026-11-01 — 不具合の修正：企業の会計（税金・持分法・子会社の資金・日の始まり）

- **作り話の前年度の法人税を払っていた**：開始時の `s.tax.last`（中間納付の計算のための作り話の前年度、`fy` なし）を5月の確定申告でも全額払い、計上していない税金の分だけ「未払法人税等」がマイナス（前払いの資産）のまま残っていた（テネシス約−$27.6B・MAGITA約−$2.3Bなど、純資産が水増し）。`fy` のない年度は確定分を払わない（`payTaxes`）。あるべき残高は `taxOwed`（今期の計上−中間納付＋前期の未払い分）。保存済みの世界は一度だけ `repairTaxes`（差額を利益剰余金から、現金は動かさない。`w.fixes.tax`）。
- **ICEのRIRU株（持分法）が帳簿になかった**：20%の持分を持ちながら「関係会社株式」が0から始まり、RIRUからの配当（投資の払い戻しとして計上）とRIRUの損失のたびにマイナスに。開始時にRIRUの純資産の持分で取得し（現金から、そのあとICEの株数を数え直して基準価格はそのまま）、損失は投資の額まで、配当は投資の額を超えた分を「受取配当金」に。保存済みの世界は一度だけ `repairStakes`（差額を利益剰余金で、`w.fixes.affil`）。
- **WAZIMAの現金が月の間マイナス**：月末の資金繰り（`treasury`）のあとにMAGITAへ月の利益を払っていた（`toParent`）。払ったあとにもう一度資金繰り。
- **日の始まりの順番**：各社の「今日」（`today`・`per.d`）を会社ごとの処理の中でリセットしていたため、先に処理された会社が後の会社に計上した損益（配当の受け取りなど）が消えうる。全社をまずリセットしてから処理する。

## 2026-11-01 — 会社の金額の表記をM/Bに・WAZIMAとMY WAYに社員がいなかった

- **M/B表記**：`CORP.fmt.money` を「$1B以上はB（$100B以上は小数1桁、兆もBのまま `$3,500.0B`）、それ未満はM（$1M未満は小数2桁 `$0.04M`）」に。決算書の `CORP.fmt.mil` も百万単位の整数をやめて同じ表記（$なし・損失は△）。運営サイトの各社の概況・決算書・事業ごとの表の単位の注記を「M=百万、B=十億」に。「本日の稼ぎ（リアルタイム）」は `CORP.fmt.moneyFine`（桁を増やして毎秒の動きが見える）。投資画面の「企業」タブ・会社のニュースの金額も同じ関数なのでM/Bに。1株あたりの値（株価・EPS・BPS・配当）はドルのまま。
- **WAZIMAとMY WAYに社員がいなかった**：一度だけの大量採用（`homecoming` → `model.welcome`）は国を読み込んだときだけで、その時点で企業の世界にまだ新しい会社がない（企業の移行より先に国を読む）と空振りし、二度と試されなかった。また、会社の組織（`W.orgs[id]`）があるだけで「採用済み」とみなしていたため、空の組織を持つ会社は採用されなかった。`model.toWelcome`（企業の世界にあり倒産しておらず、組織がないか、空の組織のまま一度も採用していない会社）で判定し、`ensure`（毎分）と締めの前にもやり直す。採用したら `orgs[id].came` に日付。

### 自分のプロフィールと二段階・三段階認証

- 運営者・開発者だけがプロフィールから設定できる。一般プレイヤーと閲覧者は設定APIを利用できない。未設定時は自分のプロフィール・アカウントアイコンと運営者一覧に赤い「！」を表示する。
- 二段階は通常パスワード＋認証アプリのTOTP。三段階はさらに別の専用確認フレーズ（12〜64文字）を要求する。三段階は追加の確認手順であり、独立した3種類の認証要素を意味するものではない。
- TOTPは [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) のSHA-1・6桁・30秒。現在と前後1ステップを許容し、最後に使用したステップを保存して再利用を拒否する。RFCの既知ベクトルで演算を検証する。
- 初回設定・再設定には現在のパスワードが必要。設定済みなら現在のTOTP（または未使用の復旧コード）、三段階なら現在の確認フレーズも必要。仮登録は10分で失効し、新しい認証アプリのコードが確認できるまで既存設定を変更しない。
- 秘密鍵は既存のホスト秘密鍵から用途別に導出した鍵で暗号化する。確認フレーズは既存のPBKDF2パスワード処理、復旧コード10個はランダム生成してSHA-256ハッシュのみを保存する。平文の復旧コードは有効化時に一度だけ返す。復旧コードはTOTPの代わりであり、三段階の確認フレーズを省略しない。
- `/api/ops/login` は全段階の検証後だけセッションを発行する。不正コードも既存のログイン失敗回数・端末/IPロックに算入する。設定APIにもログイン試行と同じ頻度制限を適用する。
- セッションに認証設定バージョンを持たせる。ゲームの通常ログイン・引き継ぎコード・設定前に作られたセッションでは、追加認証済みの管理APIに入れない。運営・セキュリティ・保管庫・バックアップ・緊急管理APIで共通検証する。既存の公開共有リンクは従来のリンク権限を継承する。通常のゲーム利用は継続できる。
- 有効化・再設定で現在のセッションだけを更新し、他の端末は管理画面に再ログインが必要。運営ライブ接続を閉じ、設定バージョンを署名鍵に含めて発行済みライブチケットも無効にする。security HOME側のログインにも同じ追加認証欄を用意する。
- 解除にも現在のパスワードと設定中の各認証が必要。認証情報を運営ログへ記録しない。
