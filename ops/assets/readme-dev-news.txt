# README DEV NEWS

プレイヤー向け DEVニュースより詳しい、保守・実装担当者のための更新記録です。運用手順と既存仕様全体は README.md を参照してください。このファイルが技術更新の正本です。

## 2026-10-25 — 開発者日記・運営者の追加認証

### ゲームの開発者日記

- メニューの「近日公開」を実際の投稿一覧に接続。タイトル・本文・画像、投稿日時、任意のドル報酬を表示する。
- 投稿を開くと既読を保存する。いいね・ブックマークは投稿とプレイヤーの複合主キーで保存し、同じ操作を再送しても増殖しない。解除とブックマーク絞り込みにも対応。
- 投稿一覧は新しい順に10件、コメントは50件ずつのカーソル方式。画像は一覧JSONに含めず、投稿を開いたときだけ認証付きAPIから取得する。
- コメントは1〜2000文字。ゲームで取得できるのは本人のコメントだけ。送信時の共有ワード・文章フィルター `server/core/filter.js` と、メッセージと同じ添付・制御文字検査 `server/core/attach.js` を通す。チャット制限中は投稿できず、メッセージと同じ送信頻度制限を使用する。
- 元のコメントと検出語は `diary_comments` にのみ保存する。運営者が見られる `detections` や DEV UNIT コメントには転記しない。開発者専用APIだけが原文と投稿者情報を返す。

### 投稿管理と表示権限

- 運営サイトに開発者専用の「開発者日記」アプリを追加。添付された青い本のアイコンを `ops/assets/diary.webp` として使用。開発者以外にはDock・デスクトップ・アプリ一覧の項目を表示しない。
- 権限はUIの非表示だけに依存せず、各 `/api/ops/diary*` 操作で既存の `ops.need` と `isDeveloper` を評価する。開発者の判定を独自に増やさず、既存の指定アカウント設定を継承する。
- タイトル100文字・本文20000文字、画像1枚、任意の報酬を投稿できる。ブラウザーで画像を最大1280pxに縮小してWebP化、サーバーではPNG/JPEG/WebPの形式・ヘッダーと512KiB上限を検査する。画像の公開URLを別途発行しない。
- 一時非表示は一覧・画像・既読・反応・コメント・報酬APIのすべてに適用する。開発者は非表示中も管理・コメント確認できる。再公開しても報酬期限と受取履歴を維持する。
- 完全削除は明示確認が必要。投稿、画像、既読、反応、コメント、受取記録をトランザクション内で削除する。受取済みの残高は回収しない。投稿IDはAUTOINCREMENTで再利用しない。
- コメント投稿者の名前と現在のアイコンを表示し、タップするとプレイヤー一覧を開いて該当プレイヤーの詳細へ移る。投稿・表示変更・削除は運営ログに記録する。コメント内容を運営ログへ残さない。
- アプリ追加後もアクティブなウィンドウが最前面に来るように、前面レイヤーの固定値16を現在の順序より高い値へ変更。多数のアプリを開いたときに背面ウィンドウが操作を遮る問題を防ぐ。

### 報酬の残高整合性

- 報酬なし、または10,000〜250,000ドルを10,000ドル刻みで選択。クライアント指定額を受取APIで信用せず、公開時に保存した金額だけを支払う。
- 期限は公開時刻から30×24時間。閲覧日時や受取ボタンを表示した日時からではない。期限の瞬間以降は拒否する。
- `(post_id, user_id)` を主キーとする `diary_claims` の `INSERT OR IGNORE` と残高加算・`rev` 増加を同一SQLiteトランザクションに置く。同時タップ、再送、別端末からの受取でも1回だけ支払う。
- 成功後は既存の残高配信 `balanceChanged` と `meDto` を使い、ゲーム画面と他端末を更新する。受取済みの再送は `paid: 0` と現在の残高を返す。

### リアルタイム反映

- 投稿・非表示切替・完全削除の確定後に `diary` イベントを既存のライブ接続で配信する。NodeはSSE、CloudflareはWebSocket。イベントは投稿IDだけを含み、コメント情報は含まない。
- 開いているゲームの日記を再取得し、接続回復時も同期する。画面が見えていて入力中でない場合は20秒間隔の補完取得を行う。運営サイトの投稿・コメント一覧は既存の更新頻度設定に従う。

### 自分のプロフィールと二段階・三段階認証

- 運営者・開発者だけがプロフィールから設定できる。一般プレイヤーと閲覧者は設定APIを利用できない。未設定時は自分のプロフィール・アカウントアイコンと運営者一覧に赤い「！」を表示する。
- 二段階は通常パスワード＋認証アプリのTOTP。三段階はさらに別の専用確認フレーズ（12〜64文字）を要求する。三段階は追加の確認手順であり、独立した3種類の認証要素を意味するものではない。
- TOTPは [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) のSHA-1・6桁・30秒。現在と前後1ステップを許容し、最後に使用したステップを保存して再利用を拒否する。RFCの既知ベクトルで演算を検証する。
- 初回設定・再設定には現在のパスワードが必要。設定済みなら現在のTOTP（または未使用の復旧コード）、三段階なら現在の確認フレーズも必要。仮登録は10分で失効し、新しい認証アプリのコードが確認できるまで既存設定を変更しない。
- 秘密鍵は既存のホスト秘密鍵から用途別に導出した鍵で暗号化する。確認フレーズは既存のPBKDF2パスワード処理、復旧コード10個はランダム生成してSHA-256ハッシュのみを保存する。平文の復旧コードは有効化時に一度だけ返す。復旧コードはTOTPの代わりであり、三段階の確認フレーズを省略しない。
- `/api/ops/login` は全段階の検証後だけセッションを発行する。不正コードも既存のログイン失敗回数・端末/IPロックに算入する。設定APIにもログイン試行と同じ頻度制限を適用する。
- セッションに認証設定バージョンを持たせる。ゲームの通常ログイン・引き継ぎコード・設定前に作られたセッションでは、追加認証済みの管理APIに入れない。運営・セキュリティ・保管庫・バックアップ・緊急管理APIで共通検証する。既存の公開共有リンクは従来のリンク権限を継承する。通常のゲーム利用は継続できる。
- 有効化・再設定で現在のセッションだけを更新し、他の端末は管理画面に再ログインが必要。運営ライブ接続を閉じ、設定バージョンを署名鍵に含めて発行済みライブチケットも無効にする。security HOME側のログインにも同じ追加認証欄を用意する。
- 解除にも現在のパスワードと設定中の各認証が必要。認証情報を運営ログへ記録しない。

### DEV UNIT連携とデータ移行

- `tools/sync_devunit_readme.cjs` は `README.md` とこのファイルをそれぞれ `ops/assets/readme-dev.txt`、`ops/assets/readme-dev-news.txt` に同期する。`predev`、`predeploy`、`prestart` で実行される。PRにも同期済みのファイルを含める。
- DEV UNITの資料セレクターから両方を検索・閲覧でき、初期選択は README DEV NEWS。既存の運営者・開発者のコメントと未読通知を引き続き使用する。日記へのプレイヤーの非公開コメントとは別の情報である。
- 追加のスキーマ移行は末尾に追記する。`diary_posts`、`diary_reads`、`diary_reactions`、`diary_comments`、`diary_claims`、`ops_mfa`、セッションの `ops_mfa_version` を追加し、既存の投稿・通貨・プロフィールを上書きしない。
- 新規テーブルは既存バックアップの `TABLES` に含める。暗号化された認証鍵の復元には元のホスト秘密鍵が必要。既存の復元仕様どおり、バックアップのスキーマ番号一致が必要。
- プレイヤーデータの永久消去時に認証設定・日記の既読・反応を消す。コメントは既存のメッセージ保持方針と同様に残し、報酬受取履歴は二重受取防止のため保持する。

### 主なAPI

| API | 用途 |
| --- | --- |
| `GET /api/diary` | 公開投稿。`before`・`bookmarks=1` |
| `GET /api/diary/image?post=ID` | 公開投稿の画像 |
| `POST /api/diary/read` | 既読保存（`post`） |
| `POST /api/diary/react` | `post`・`kind: liked/bookmarked`・`on` |
| `GET/POST /api/diary/comments` | 本人のコメント取得／送信 |
| `POST /api/diary/claim` | 報酬受取（`post`） |
| `GET/POST /api/ops/diary` | 開発者専用の一覧／公開 |
| `GET /api/ops/diary/image` | 非表示投稿を含む管理用画像 |
| `GET /api/ops/diary/comments` | 開発者専用のコメント・原文・投稿者 |
| `POST /api/ops/diary/visibility` | 一時非表示／再公開 |
| `POST /api/ops/diary/delete` | 完全削除（`confirm: true`） |
| `GET /api/ops/profile` | 自分のプロフィールと認証状態 |
| `POST /api/ops/profile/mfa/begin` | 仮登録 |
| `POST /api/ops/profile/mfa/enable` | 新コード検証・有効化 |
| `POST /api/ops/profile/mfa/disable` | 追加認証解除 |

### 検証

`npm test` は既存244件＋追加9件の計253件。日記の権限境界、非公開コメント、共有フィルター、二重受取・期限、一時非表示・再公開・削除、ページング、ライブ配信、認証設定・再利用防止・復旧・ゲームセッションからの迂回防止を検証する。TOTP・復旧コードの同時使用も1件だけ成功することを確認し、認証テストの時刻を固定して30秒境界の偶発的な失敗を防ぐ。

`node tools/check_ops_desktop.cjs` はPlaywrightとChromiumを用いた既存運営サイトの40項目。開発者16アプリ・運営者14アプリ・閲覧者8アプリ、ウィンドウ操作、資料切替、ログ・権限・縦持ち表示を確認済み。`OPS_BROWSER_EXECUTABLE` でブラウザーを指定できる。

追加の実ブラウザー確認では、画像と250k報酬を付けた投稿、ゲームからのいいね・ブックマーク・本人コメント・報酬受取、ライブ投稿・一時非表示の即時反映、開発者から投稿者詳細への遷移、README両資料の表示、三段階認証の設定とログアウト後の再ログイン、一般運営者からの日記アプリ非表示を確認した。
