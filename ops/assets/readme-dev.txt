## 遊び方

| 方法 | 手順 |
| --- | --- |
| オンラインで遊ぶ | 公開した URL を開く → 起動画面の **スタート** |

| 全画面にする | Android: 最初のタップで自動的に全画面＋横向きロック。iPhone: Safari の共有 →「ホーム画面に追加」から起動すると全画面になります |
| 起動 | 毎回、製作会社のロゴ動画（スキップ不可）→ タイトル画面（BGM は少し小さめの音量でループ）。ブラウザは音を出す前にタップが必要なため、最初に「TAP TO START」が出ます（Android アプリでは出ません） |

- 縦持ちでも画面が自動で 90° 回転し、横画面レイアウトのまま遊べます。

### 5時間クエストの追加段階

同じ種類は既存の段階式表示にまとまり、進捗は累計です。以下は倍率適用前のゲーム内ドル報酬（k = 1,000、M = 1,000,000）です。

| 条件 | 累計目標 | 各段階の基本報酬（目標と同じ順） |
| --- | --- | --- |
| カジノを回す（既存の1・2・5・10回の続き） | 20 / 30 / 40 / 50 / 60 / 70 / 80 / 90 / 100回 | 25k / 35k / 50k / 75k / 80k / 80k / 80k / 100k / 100k |
| 友達に雪だるまを送る | 1 / 2 / 3 / 5 / 10回 | 10k / 20k / 30k / 50k / 120k |
| BARを揃えて当たる | 1 / 2 / 3回 | 10k / 15k / 20k |
| 銃を中央5列すべて揃えて当たる | 1 / 2 / 3 / 4 / 5回 | 5k / 6k / 7k / 8k / 9k |
| カジノで使う（賭けたトークンをドル換算） | $30k / 100k / 200k / 500k / 1M / 2M / 3M | 10k / 20k / 30k / 35k / 65k / 85k / 115k |
| カジノでコンボする（既存の2・3・4コンボの続き） | 5 / 6 / 7 / 8コンボ | 100k / 250k / 400k / 950k |
| 稼ぎに参加する（友達と稼ぐ、既存の1回の続き） | 2 / 3 / 4 / 5 / 6回 | 10k / 15k / 20k / 25k / 35k |

BARは中央の当たりラインで配当が出たスピンを1回として数えます（2〜5個揃い）。銃は4個揃いでは進みません。雪だるまは送信成功時に送信者の進捗へ加算し、受け取る側には加算しません。
5時間ごとのリセット・報酬額による色分け・受け取り操作・「友達と稼ぐ」のカウント倍率は、既存のクエストと共通です。
カジノで使った額は、5時間内に賭けたトークンの累計を **1トークン＝$10** で換算します。当たりの払い戻しは差し引きません。トークンの購入・送金・Shop・プレゼントなどの支出は含めません。
コンボの進捗は連続当たりの最高回数です。「クエストをクリアする」は報酬の受け取り時ではなく達成時に数え、他の期間のクエストやクリア個数のクエスト自身も含みます。

### レベルアップとリセットチケット

今後のプレイヤーレベルアップ1回につき **5時間クエストリセットチケット1枚** を配布します。さらに **Lv5・10・15・20・25…以降も5の倍数に到達するたびに、デイリークエストリセットチケット1枚** を追加で配布します。一括受け取りなどで複数レベル上がった場合も、通過したレベル分をすべて獲得します。新規登録時のLv1や導入前のレベルアップには配布しません。

次の自然更新時刻は変わらず、他の期間の進捗、獲得済み報酬、レベルは保持します。チケットは自然更新や再ログインでも残り、連打や通信の再送で重複消費しないようサーバーで確認します。

### VIPのカート購入とチケット

VIPの30日・40日まとめ買いプランは、プラン1個ごとに **5時間クエストリセットチケット1枚** が付きます。10日・20日プランや通常の日数購入には付きません。まとめ買いプランをタップし、確認で「はい」を選ぶとカートに追加されます。購入ボタンにプランと個数のバッジを表示し、複数プランを一度の操作で購入できます。料金・おまけ日数・チケットはサーバーが計算し、残高や追加日数の上限を確認して一括で反映します。

通常の日数選択は＋／−を使います。1・7・30日のショートカット、電卓による日数入力、所持コインの重複表示は削除しました。VIP有効中のカジノの当たりは **1 EXP**、クエスト達成の0.1 EXPとULTRA BIG WINの250 EXPは従来どおりです。

### クエストのPRO・ULTRA

すべての期間のクエストで、**STEPを達成したときに1回だけ、STEPごとに独立して** 抽選します。結果はサーバーに保存され、受け取り前のカードに状態と実際の報酬を表示します。

| 状態 | 確率 | そのSTEPの報酬 |
| --- | --- | --- |
| 通常 | 94.9% | 基本報酬 |
| PRO | 5% | 基本報酬の3倍 |
| ULTRA | 0.1% | 基本報酬の6倍＋ロイヤルコイン8枚 |

状態は重複せず、次のSTEPには引き継ぎません。再読み込みや受け取りで再抽選せず、**一括受け取りでも各STEPの保存済みの報酬を合算**します（ULTRAが2件ならロイヤルコイン16枚）。報酬とロイヤルコインは受け取り時に1回だけ付与し、受け取らずに期限が切れた分は失効します。導入前に達成済みのSTEPは通常報酬です。経験値と基本報酬による色分けは従来どおりです。

## 無料サーバーで公開する（Cloudflare）

ゲーム画面・API・データベースがすべて Cloudflare の無料プランに収まります。
必要なのは Cloudflare の無料アカウントと、この GitHub リポジトリだけです。

1. [Cloudflare に無料登録](https://dash.cloudflare.com/sign-up) してログイン
2. 左のメニュー **Workers & Pages** →「**作成（Create）**」→「**リポジトリをインポート（Import a repository）**」
3. GitHub と連携して `Special-Casino-2026` を選ぶ
4. 設定画面ではプロジェクト名を **`blockbuster-reels`** のままにし、ビルドコマンドは空欄、デプロイコマンドは `npx wrangler deploy`（初期値）のまま
   - 公開に使うブランチ（本番ブランチ）は、この作業をした `claude/epic-gates-fmo9j7` を選ぶか、先に GitHub で main に取り込んで（マージして）ください
5. 「**デプロイ**」を押す → 1〜2 分で `https://blockbuster-reels.<あなたのアカウント名>.workers.dev` が公開 URL になります

これで完成です。以後は GitHub のブランチを更新するたびに自動で再デプロイされ、**プレイヤーのデータはそのまま残ります**。

> 絶対に変えないでください: `wrangler.jsonc` の `"name"`（`blockbuster-reels`）と `"migrations"` の行。
> 全プレイヤーのアカウントとお金はこの名前に結び付いたデータベース（Durable Object）に保存されています。

- パソコンからコマンドで公開する場合: Node.js を入れて `npm install` → `npx wrangler login` → `npm run deploy`
- 自分のパソコンで試す場合: `npm install` → `npm run dev` → http://localhost:8787
- 独自ドメインを使う場合: Cloudflare の Worker の「設定 → ドメインとルート」から追加できます

### 保管庫を R2 につなぐ（50GB）

開発者専用保管庫のファイルは、つなぐ前はゲームのデータベースに入ります（Workers Paid で全体 3GB まで。データベースはプレイヤーのデータと共用のため）。
Cloudflare の **R2**（ファイル置き場）につなぐと **全体 50GB・1 ファイル 2000MB** まで入り、データベースは軽いままです（8MB ずつ送るので速くなります）。

| 料金（月） | 内容 |
| --- | --- |
| R2 | 10GB まで無料、それ以上は 1GB あたり 0.015 ドル（50GB 使い切りで約 0.6 ドル、80GB で約 1.05 ドル）。取り出しの通信料は無料 |

1. Cloudflare の **Workers & Pages → プラン** で **Workers Paid**（済み）
2. **R2** を有効にして、**バケットを作成**（名前は `blockbuster-reels-vault`、ほかは初期値）
3. `wrangler.jsonc` に `"r2_buckets": [{ "binding": "VAULT", "bucket_name": "blockbuster-reels-vault" }]` を追加して main に反映
   - バケットを作る前に追加すると、デプロイが失敗します（ゲームは前の版のまま動き続けます）
4. 運営サイトの保管庫で「編集する」（開発者コード）を押すと、データベースにあったファイルが自動で R2 に移ります（「R2 へ移動」の表示が出ます）

運営者どうしの **共有保管庫** と各運営者の **個人保管庫** も同じ容量（R2 なら 50GB）を使います（1 人 1GB まで。超えるには開発者の承認と上限の設定が必要。下の「サーバー運営サイト」の **保管庫**）。
保管庫のファイルが自動で消えることはありません（消せるのは使っている人の「削除」だけ。開発者がバックアップしたものは、削除されてもバックアップに残ります）。

### 設定（任意）

Cloudflare の Worker の「設定 → 変数とシークレット」で追加できます（どれも省略可。`wrangler.jsonc` の `"keep_vars": true` で、デプロイしても消えません）。

| 変数 | 内容 |
| --- | --- |
| `ADMIN_TOKEN`（シークレット） | 管理コマンド用の合言葉（24 文字以上）。設定すると下の管理コマンドが使えます |
| `CF_TURN_KEY_ID` / `CF_TURN_API_TOKEN`（シークレット） | 通話がつながりにくい回線向けの中継サーバー。Cloudflare の **Realtime → TURN** で作成したキー ID と API トークン（毎月 1,000 GB まで無料） |
| `REGISTRATION` | `closed` で新規登録を止める（既存プレイヤーは遊べます） |
| `START_TOKENS` / `START_DOLLARS` / `START_COINS` | 新規プレイヤーの初期残高（既定 0 / 5,008,159 / 74） |
| `MAX_TRANSFER_TOKENS` / `MAX_TRANSFER_DOLLARS` | 1 回の送金上限 |
| `DAILY_REQUEST_LIMIT` / `DAILY_MB_LIMIT` | 自前の 1 日の上限（リクエスト数 / 送信 MB、0 = なし）。超えるとその日（0:00 UTC まで）はメンテナンス表示。Cloudflare の無料枠の上限では設定しなくても表示されます |
| `LOGIN_BONUS` | `false` でログインボーナスを止める |
| `QUESTS` | `false` でクエストの報酬を止める |
| `OPERATORS` | サーバー運営サイト（`/ops/`）に入れるアカウントのユーザー名（カンマ区切り、既定: `taku`） |
| `DEVELOPER` | 開発者のアカウントのユーザー名（`OPERATORS` のひとり、既定: `taku`）。**アクセス禁止・BAN・永久BAN はどこからもできず**（運営サイト・管理コマンド・同じ端末のほかのアカウントの BAN でも止まりません）、運営権もなくなりません。**開発者コード**を登録できるのもこのアカウントだけです |
| `PUSH_CONTACT` | スマホ通知（Web Push）の送信元として通知サービスに伝える連絡先（`mailto:` か `https:`。空ならゲームの公開 URL）。通知の鍵はサーバーが最初に自動で作って保存します |
| `ACCOUNTS_PER_DEVICE` | 1 つの端末で作れるアカウントの数（既定 2、0 で制限なし） |
| `STRIPE_SECRET_KEY`（シークレット） | 開発者支援の決済（Stripe）の API キー。**制限付きキー（`rk_live_…`）推奨**（下の「開発者支援（課金）を始める」）。テストは `rk_test_…` / `sk_test_…` |
| `STRIPE_WEBHOOK_SECRET`（シークレット） | Stripe の Webhook の署名シークレット（`whsec_…`。入れ替えるあいだはカンマ区切りで 2 つ） |
| `PUBLIC_URL` | ゲームの公開 URL（例 `https://blockbuster-reels.xxx.workers.dev`、最後の `/` なし）。決済のあとに戻るページになります |
| `PAY_METHODS` | 使う支払い方法（既定 `paypay,konbini`。`paypay` だけにもできます） |
| `PAY_DAILY_LIMIT` | 1 人が 24 時間に支払える上限（円、既定 10000） |
| `SELLER_NAME` / `SELLER_ADDRESS` / `SELLER_PHONE` / `SELLER_EMAIL` / `SELLER_HEAD` / `SELLER_HOURS` | 特定商取引法に基づく表記（販売事業者・所在地・電話番号・メールアドレス・運営統括責任者・お問い合わせ受付時間）。空の項目は「ご請求があれば遅滞なく開示いたします」と表示 |
| `VAULT_MAX_MB` / `VAULT_FILE_MB` | 開発者専用保管庫の容量（全体 / 1 ファイル、MB。既定は R2 につないだとき 51200 / 2000、つなぐ前は Workers Paid で 3072 / 2000、無料プランで 1024 / 300） |
| `VAULT_PIECE_MB` | 保管庫に 1 回で送る大きさ（MB、1〜16。R2 につないだときだけ。既定は Workers Paid で 8、無料プランで 1） |
| `VAULT_FREE_MB` | 共有保管庫で運営者 1 人が開発者の承認なしに使える大きさ（MB、既定 1024 = 1GB）。超えるには開発者の承認と上限の設定が必要 |
| `CF_PLAN` | 契約中の Cloudflare のプラン（`paid` か `free`、`wrangler.jsonc` に `paid` と記入済み）。保管庫の大きさと「サーバー」タブの料金に使います |
| `CF_ACCOUNT_ID` / `CF_API_TOKEN` | 「サーバー」タブに Cloudflare 自身の今月の数字（リクエスト・エラー・CPU 時間・R2・データベース）も出すとき。アカウント ID と、**Account Analytics: 読み取り** だけの API トークン（シークレット） |
| `STRIPE_API_VERSION` | Stripe の API バージョン（既定 `2025-09-30.clover`。通常は不要） |
| `DISCORD_WEBHOOK_URL`（シークレット） | 開発者への通知を送る Discord のチャンネルの Webhook の URL（下の「Discord に通知する」） |

ホーム通話は端末どうしを直接つなぎます。ほとんどの Wi-Fi・モバイル回線はそのままつながりますが、
一部の回線でつながらない場合は上の TURN を設定してください。マイクの使用には HTTPS が必要です（workers.dev は HTTPS です）。

### Discord に通知する

開発者がすぐ知りたいことを、Discord のチャンネルに送ります：**緊急停止とロックダウン（とその解除）・セキュリティシールドによる攻撃元の自動ブロック・自動フィルタリングによるチャット停止・通報・報告／意見案・開発者支援の入金と返金と確認が必要な注文・不正な決済通知・開発者コードの入力ミス・運営権の付与と剥奪・自動バックアップの失敗・共有保管庫の容量の申請（開発者の承認待ち）・新しい版の本番反映**（反映のあと最初のアクセスで届きます）。
**ゲーム・運営サイト・サーバーが危険な状況**（緊急停止・ロックダウン・攻撃元の自動ブロック・画面を見る機能の強制終了）のときは **【危険】** を付け、何がどれだけふだんを超えたか・理由・多いアドレスや API などの状況をできるだけ詳しく書き、**運営サイトと security HOME（`/sec/`）の URL を両方** 添えます。ふつうの通知は運営ログと同じ 1 行の要約と運営サイトへのリンクだけ（チャットの文面は送りません）。近い時間のものは 1 通にまとめ、1 分に 20 件を超えた分は件数だけ知らせます。誰かへのメンション（@everyone など）にはならず、リンクのプレビューも出ません。

1. Discord で通知を受け取るサーバーの **サーバー設定 → 連携サービス → ウェブフック → 新しいウェブフック**。チャンネルを選んで **ウェブフック URL をコピー**
2. Cloudflare の Worker の「設定 → 変数とシークレット」で、シークレット `DISCORD_WEBHOOK_URL` にその URL を入れてデプロイ
3. 運営サイトの「サーバー」タブの「Discord 通知」が「オン」になります。開発者は「テスト送信」で届くか確かめられます

Webhook の URL を知っている人は誰でもそのチャンネルに書き込めるので、人に見せないでください（漏れたら Discord でそのウェブフックを削除して作り直します）。

### 開発者支援（課金）を始める

決済は **Stripe**（PayPay・コンビニ決済に対応した決済代行会社）を使います。設定するまでは購入画面に「準備中」と出て、購入はできません。

1. [Stripe](https://stripe.com/jp) でアカウントを作り、本人確認と **売上の振込先（開発者の銀行口座）** を登録
2. ダッシュボードの「設定 → 決済手段」で **PayPay** と **コンビニ決済** を申請して有効にする（どちらも審査があります。下の注意）
3. 「開発者 → API キー」で **制限付きキー** を作る。権限は **Checkout Sessions：書き込み** と **PaymentIntents：読み取り** だけ（万一漏れても被害が小さくなります）
4. 「開発者 → Webhook」でエンドポイントを追加：URL は `https://（公開URL）/api/pay/webhook`、イベントは
   `checkout.session.completed`・`checkout.session.async_payment_succeeded`・`checkout.session.async_payment_failed`・`checkout.session.expired`・`charge.refunded`。
   表示される **署名シークレット**（`whsec_…`）を控える
5. Cloudflare の Worker の「設定 → 変数とシークレット」に、シークレットとして `STRIPE_SECRET_KEY`・`STRIPE_WEBHOOK_SECRET`、
   変数として `PUBLIC_URL` と `SELLER_NAME`・`SELLER_ADDRESS`・`SELLER_PHONE`・`SELLER_EMAIL`（必要なら `SELLER_HEAD`・`SELLER_HOURS`）を入れて再デプロイ
6. 最初は **テスト用のキー**（`rk_test_…` とテスト用の `whsec_…`）で試すと、本物のお金を動かさずに最後まで確かめられます（購入画面と運営サイトに「テストモード」と出ます）
7. 運営サイトの **「課金」タブ**（開発者だけに表示）のいちばん上で、設定が正しいか・Webhook の送信先を確認できます

安全のための仕組み:

- 支払いは Stripe のお支払いページで行うので、PayPay のログイン情報などはこのサーバーに届きません。金額はサーバーだけが決めます（ブラウザから送られた金額は使いません）
- ロイヤルコインは **Stripe に問い合わせて確認できた支払いにだけ**、**1 回だけ** 付与します。Webhook は署名（HMAC-SHA256・受け取ったままのデータで照合・5 分以内）を確かめ、そのうえでサーバーが Stripe に注文の中身（注文番号・金額・円・本番 / テスト）を問い合わせて一致したときだけ付与。一致しない注文は付与せず「確認中」にして運営ログに残します。Webhook が届かなかった場合も、プレイヤーが画面を開いたときや定期処理で Stripe に確認します
- 注文番号はランダムな 128 ビット、ほかの人の注文は見られません。返金されるとその分のロイヤルコインを回収します
- 18 歳以上のみ・1 人 24 時間で 10,000 円まで・支払い待ちの注文の数の上限・回数の制限。BAN 中は購入できません
- 注文・入金・コンビニの支払い番号・返金・不一致・不正な通知・開発者の返信は、すべて運営ログ（改ざん検知つき）に記録されます。注文はバックアップにも含まれます
- 秘密の鍵は Cloudflare のシークレットにだけ置き、リポジトリには書きません

注意:

- **最低金額**：PayPay は合計 50 円から、コンビニ決済は合計 120 円から（Stripe の決まり）。開発者支援I だけなら PayPay は 5 口・コンビニは 12 口から買えます（画面で案内します）
- **コンビニ決済の手数料** は 1 件あたり 3.6%・最低 120 円なので、少額の購入では手数料で売上がほとんど残りません。PayPay だけにするなら `PAY_METHODS=paypay`
- **コンビニ決済の返金** は 1 件 275 円の手数料がかかります（返金は Stripe のダッシュボードから。返金されるとロイヤルコインは自動で回収されます）
- **審査**：PayPay とコンビニ決済には Stripe と提携先の審査があります。どちらも商品・画像・価格が日本語でサイトに載っていて、トップページから特定商取引法に基づく表記へのリンクがあることが条件です。
  PayPay は事業者名・住所・法人番号が国税庁の法人番号公表サイトと一致している必要があります（主に法人向け）。
  コンビニ決済は審査に約 30 日かかり、「開業から 3 年未満の個人事業主」「ギャンブル」などは対象外と明記されているため、カジノを題材にしたゲームは審査に通らない可能性があります
- 特定商取引法に基づく表記はログインなしで `https://（公開URL）/law` から見られ、タイトル画面の左下からもリンクしています（審査の申請にも使えます）。`SELLER_*` を設定してください

### サーバー運営サイト

`https://（公開URL）/ops/` を開き、運営者のアカウント（既定は **TAKU**、`OPERATORS` で変更）の名前とパスワードで
ログインします（入力は最初の 1 回だけ。そのブラウザに記憶されます。それ以外のアカウントはログインできません）。
**名前かパスワードを続けて 2 回間違えると入力制限**になり、そのブラウザは 5 分間入力できません（そのあとまた 2 回間違えると 10 分、20 分、40 分…と倍になり、ログインできるか、間違いのないまま 1 日たつと元に戻ります。ブラウザを変えて回避されないよう、同じ回線〔IP アドレス〕から合わせて 10 回間違えると回線ごと同じように待ちになります。この制限はログに残しません）。**その日（日本時間）はじめて運営サイトを開くと「ログイン」ボタンの画面**になり、押すと入れます（開発者・運営者・閲覧者の全員。パスワードでログインした日はそれがその日のログイン。security HOME のログインは数えません）。これは **「ログインログ」**（運営者タブのいちばん下・**開発者だけ**が見られる。運営ログとは別）に 1 人 1 日 1 回、時刻・役割・名前・ボタンかパスワードか・端末とブラウザ（例 iPhone / Safari）で残ります。白を基調にした画面で、

- **プレイヤー**: プレイヤー名・オンライン状況・資産（トークン・$・コインと $ 換算の合計）・18歳以上（はい / いいえ / 未回答）・引き継ぎコード・パスワード・処分。名前で検索、オンライン / 返信待ち / 検知あり / 処分中で絞り込み、並べ替え（15 秒ごとに更新、返信待ちの人が先頭）。アイコンに **「返信待ち」**（公式へのメッセージに未返信）と **「検知」**（チャットの不適切な言葉）の印
- **「画面」の列**: オンラインのプレイヤーの **「見る」** で、そのプレイヤーのゲーム画面をリアルタイムで見られます（操作はできず、見ていることは本人に知らされません。下の「運営の画面を見る機能」）。**★** はその運営者だけのお気に入り（絞り込みは「★ お気に入り」）
- **アイコンをタップ**: そのプレイヤーと **Ice Smoker公式の本物のチャット画面**（開くとプレイヤーのメッセージに既読がつきます）。送るメッセージは「【件名】／〇〇様／要件（文字数無制限）／Ice Smoker公式より」の形（送られる文面を確認してから送信）。「送金」で公式から **$0〜$10,000,000**（1 万〜1,000 万のボタンと金額入力、ひとこと付き）。2 日以上返信がないと、そのメッセージに既読をつけて公式が自動で返信します
- **行をタップ（詳細）**: 登録日・18歳以上の答えと日時・遊んでいる累計時間・最長連続オンライン日（日本時間 6:00 区切りで続けてログインした日数の最長）・今の連続日数・ログイン日数・レベル・通報の件数・検知・記録・使った端末と同じ端末のほかのアカウント
- 詳細には **ゲームのバージョン**（最新なら「最新」、古いなら「DEV7（最新は DEV8）」のように、ビルド・端末〔Android・iPhone・Windows など〕・確認した日時つき）
- 操作: アクセス禁止（1 週間）・BAN（30 日）・永久BAN・処分の解除・端末の BAN から外す・引き継ぎコードの再発行・パスワードの再設定。
  処分するとそのプレイヤーのゲームは **すぐにタイトル画面に戻り、解除されるまでそこから先へ進めません**（「Ice Smoker公式より／あなたは〇〇（日時）に公式よりアクセス禁止されました／期間」を表示。読み込み直しても同じ。ログインは保ったままなので、解除されるか期間が終わると 20 秒ほどで「解除されました」→「ゲームに戻る」）。
  公式から **「【アクセス禁止のお知らせ】…あなたは〇〇に公式よりアクセス禁止されました。期間：…」** が届き、解除したとき・期間が終わったときも **「【…解除のお知らせ】」** が届きます。処分中は、同じ端末で新しいアカウントも作れません（アクセス禁止も含む）
- **通報**: 日時・通報した人・対象・種類・内容と、対象の情報（レベル・所持金・登録日・オンライン・18歳以上・処分）・ふたりの関係・最近のメッセージ・検知。**受理**（公式から通報者へ $60万 / $120万 / $240万 と「ありがとうございます！…受理されました！運営一同心から協力に感謝いたします！」）か **受理しない**
- **検知**: 送った人・相手（グループ・ホーム・ハブ）・日時と、**原文（検知した言葉を赤で表示）**。確認済みにすると印が消えます
- **報告・意見案**: 公式に届いた報告・意見案と、星のフィードバック。チャットで返信・対応済み。意見案は **「採用する」** で、公式からその人へ **50,000 スピントークン** と感謝のメッセージ（1 つの意見案につき 1 回、対応済みにもなります）
- **アーカイブ**（プレイヤーアーカイブ）: **永久BAN** と **アカウント削除** をしたプレイヤーは一覧からここに移り、**入った瞬間から 90 日後にその人のデータが自動で削除** されます（ログイン・端末・パスワードと引き継ぎコード・登録した IP や端末の情報・お金・車・フレンド・アイテムなど）。**会話とログは無期限で保存** され（フレンドやグループとの会話・公式や NPC との会話・ホームのチャット・通報・検知・意見案・送金の記録）、アカウントは「〇〇（削除済み）」という名前だけになります（誰もログインできず、元にも戻せません。名前は新しいプレイヤーが使えるようになります）。法律で 7 年残す決まりがある開発者支援の支払い記録と、書き換えられない運営ログも残ります。永久BAN は運営が解除でき、解除すると一覧に戻ってタイマーも消えます。長くオフラインなだけのプレイヤーは消えません
- **アカウント削除**（プレイヤーの詳細の一番下。**開発者のアカウントにだけ表示**）: 開発者コードを入れると、そのプレイヤーと **同じ端末（端末 ID）のサブ垢** がすぐにすべての端末でログアウトされ、アーカイブへ移ります。**削除は開発者でも取り消せません**（ログインもできなくなります）。運営者のアカウントは削除できません。削除は運営ログ（セキュリティ）に残ります
- **運営チャット**: 運営者だけの連絡用。運営者の一覧（**緑＝運営サイトにいる・青＝ゲーム中**、ほかは **最終オンラインの日時**）、いま何人オンラインか、**全体チャット**（運営者全員）と **個人チャット**（1 対 1、既読つき）。未読はタブの数字。送ったメッセージは取り消せません。**開発者はほかの運営者どうしの個人チャットも閲覧できます**（ページにもそう表示）。**DEV11**：メッセージの「＠」（または入力中に @ を打つ）で **プレイヤーを引用** でき（メッセージではその人の名前になり、タップでプレイヤーの詳細が開きます）、候補のいちばん上の **「@開発者」は特別タグ** で、使うと開発者に **すぐ知らせます**（開発者の運営サイトに通知の帯・スマホ通知・Discord）。「ログ」で **運営ログのどの記録でも引用** でき（記録の要約がカードで表示され、タップでその記録が開きます。ログの「詳細」の「運営チャットで引用」からも）。**全体チャットではグループ通話**ができ（「通話に参加」）、**人数も時間も制限なし**・**高音質（Opus 128kbps・エコーとノイズの除去）**。ほかのタブを見ている間も通話は続き、右下の「通話中」から戻れます（ミュート・退出）。通話の合図は運営サイト専用のリアルタイム接続で送られ、ゲームの接続とは別です（閲覧者は使えません）
- **サーバー**（運営者全員）: **今月の使用量**（込みの分に対する割合の最大の項目）が **10% を超えると緑・30% で青・50% で紫・70% で赤** に変わり、サーバーのタブのボタンも（どのタブにいても）同じ色になります。**通信量の内訳**（映像通信＝友達の観戦と運営の画面を見る機能／プレイヤーの処理＝ゲームと運営サイト／音声＝通話の合図。通話の音声そのものは端末どうしで直接つながります）も出ます。サーバーの今をリアルタイムで。プレイヤーの接続数・運営者のオンライン数・1 秒あたりのリクエストと送信量（帯域）・ライブ通信・今日の合計、**直近 5 分のグラフ（1 秒ごと）**、契約中のプランの中身、**今月の料金の目安**（込みの分と使った分）、データベースの大きさと件数、保管庫、Cloudflare の集計（`CF_ACCOUNT_ID` / `CF_API_TOKEN` を入れたとき）
- **バックアップ**（サーバータブの下。**開発者のアカウントにだけ表示**）: 保管庫以外の全データ（全プレイヤー・お金・チャット・ログなど）を **5 時間ごと・12 時間ごと・1 日ごと・手動のみ** から選んで自動でバックアップ（自動のものは新しい 10 / 30 / 100 個かすべてを残す。手動のものは削除するまで残る）。**開く・設定・実行・ダウンロード・削除のすべてに開発者コードが必要**で、開発者以外には画面すら出ません。中身は開発者のブラウザで作った鍵（ECDH P-256）で暗号化され、その鍵は開発者コードでしか開けない形（PBKDF2 60 万回 + AES-GCM）でだけサーバーにあるので、**サーバーの管理者やデータベースを見た人でも中身を読めません**。ダウンロードはブラウザの中で開いて JSON ファイルとして保存（管理コマンドの `import` で復元できます）。保存先は R2（つないだとき）かデータベース。開発者コードを変えると鍵も新しいコードにかけ直します。すべて運営ログ（セキュリティ）に記録
- **緊急停止**: 保管庫を除くサーバーの使用量（リクエスト・送信量・ライブ通信・データベースの増え方。運営サイトの分は別にも）を 1 分ごとに **ふだん（直近 1 日ほどの平均）** と比べ、**10 倍以上かつ下限（リクエスト 2 万回/分・送信 500MB/分・ライブ通信 3 万件/分・データベース 30MB/分、運営サイトは 3,000 回/分・150MB/分。ふつうに人が増えたくらいでは止まらない量）以上の状態が 2 分続くと**、取得できる限りの情報（毎分の数字・ふだんの値・多かったアドレス / アカウント / API・データベース）を緊急ログに書いてから **サーバーを全停止** します（制限で弾いたアクセスは数えないので、1 か所からの連打だけでは止まりません）。**画面を見る機能もすべて強制終了**します（その旨も Discord に報告）。停止中はプレイヤーにメンテナンス表示、運営者にも停止中の画面が出て、**開発者だけが入れて緊急ログを見て、開発者コードで解除** できます（再起動やデプロイでも停止は続きます。解除後 30 分は自動停止しません）。開発者はサーバータブから手動でも止められます
- **セキュリティ**（運営者全員）: すべての API リクエストを最初に点検する **セキュリティシールド**（`server/core/shield.js`）の状況をリアルタイムで。直近 5 分の攻撃・探索・フラッド・ログイン失敗・ブロック数、脅威レベル、脅威スコアの高いアドレス、ブロック中の一覧。シールドは、ゲームが決して送らないもの（パストラバーサル、SQL／スクリプト／テンプレートのインジェクション、スキャナー／攻撃ツール、他ソフトへの探索、人の操作ではありえない連打）を遮断し、攻撃元のアドレス・アカウント・端末を自動でブロックします（戻ってくるたび時間が倍に。ロードバランサ／プロキシ経由の実際の接続元で判断し、同じ回線の大勢のプレイヤーは巻き込みません）。**ロックダウンに至らない攻撃は、このタブから運営が手動でブロック・解除** できます（記録に残ります）。ブロックはデータベースに保存され、再起動しても忘れません
- **ロックダウン**（最終手段）: シールドが **防御の突破**（多数のアドレスからの同時攻撃や、サーバーの鍵〔管理トークン・開発者コード〕への総当たり）を検知すると、または運営が security HOME から手動で、**ロックダウン** を発動します。発動すると全員（プレイヤーは「緊急メンテナンス」・運営者・開発者も）が締め出され、サーバーは **ログ以外を停止**、**外部通信を遮断**（Stripe・Cloudflare・通知・TURN を呼ばない）、取得できる限りの攻撃情報と運営ログの整合性チェックを **緊急ログ** に記録し、鍵があれば暗号化バックアップを取って **重要な情報をできる限り守ります**。**最長 1 か月で自動解除**、運営者はいつでも手動で解除できます。既存の緊急停止・メンテナンス表示など数々の緊急システムと統合されています
- **security HOME**（`/sec/`、運営者だけ）: TWO STATE とは独立した HTML 環境の、運営の **最終安全基地**。最も厳しい CSP で、外部への読み込みはいっさいありません。サーバーとTWO STATE のセキュリティ状況をリアルタイムに表示（左）、運営サイトと同じ運営ログ（右）、運営者どうしの **暗号化された連絡チャンネル**（メッセージはサーバーに封印して保存。データベースを直接見ても読めません）を備え、**ロックダウンの発動・解除だけ** ができます（プレイヤー管理・送金・保管庫などの主要な運営操作はできません）。ロックダウン中もここだけは使えます。運営サイトからログインしたのと同じ運営者アカウントで入れます
- **更新頻度**（右上）: **極めて高い**（一覧 3 秒・サーバーとチャット 1 秒ごと）/ **高い**（5 秒・2 秒）/ **通常**（15 秒・5 秒）/ **遅い**（60 秒・15 秒）/ **極めて遅い**（5 分・60 秒）。**変えられるのは開発者だけ**で、選んだものが運営者全員の運営サイトと security HOME に反映されます（ほかの運営者には表示だけ。変更は運営ログに記録）
- **運営者**: 運営者の一覧（`OPERATORS` と、運営サイトで付与・剥奪した人）と閲覧者の一覧。**権限（運営権・閲覧者）の付与と剥奪は開発者ただ一人だけができ**（ほかの運営者には付与のボタンも出ず、サーバーも受け付けません）、**そのたびに開発者だけが知っている「開発者コード」が必要**です（プレイヤー名を入れて「運営権を付与」か「閲覧者にする」）。
  リポジトリは公開されているので、コードはどこにも書かれていません：**最初に一度だけ、開発者のアカウントでこのタブの「開発者コードを登録」から登録**してください（サーバーにはパスワードと同じく元に戻せない形でだけ保存。変更は今のコードが必要）。間違ったコードは 1 時間に同じ接続から 5 回・全体で 30 回までで、すべて運営ログに残ります。
  **剥奪** すると、その人は **すぐにすべての端末でログアウト** され（ゲームでは「運営権が剥奪されたため、ログアウトされました」）、**運営サイトにはログインできなくなります**（ゲームには一般のプレイヤーとしてログインできます）。開発者の運営権は剥奪できません。付与・剥奪・コードの登録と入力ミスは運営ログに記録
- **閲覧者**（DEV11）: 運営サイトと security HOME を **見ることだけ** ができる権限です（開発者が「閲覧者にする」で付与）。見られるのは 通報・検知・報告 / 意見案・ログ・運営者・セキュリティ・サーバー の各タブと、security HOME の状況とログだけ。**プレイヤー一覧・アーカイブ・保管庫・運営チャット・公式チャット・バックアップ・課金は見られず、送金・処分・ブロック・ロックダウンなどの操作は一切できません**（ボタンも出ません）。ログはリクエストの情報（IP アドレス・端末）と詳細を除いた要約だけです。
  **システム的に分離** しています：閲覧者が運営サイトにログインすると「閲覧専用」のログインになり、サーバーは決められた読み取りのリストに入っているものだけを通します（それ以外はゲームの操作も含めてすべて拒否。各機能も運営者か閲覧者かを自分で確かめる二重の守り）。**剥奪するとその場で閲覧専用のログインが終わり、運営サイトと security HOME は 2 秒以内に自動でログアウト**して画面の内容も消えます（ゲームはそのまま遊べます）。閲覧者のプレイヤーには、運営サイトのプレイヤー一覧とゲームの自分のプロフィールに **「閲覧者」のバッジ** が付きます。閲覧者を運営者にすると閲覧者ではなくなります。付与・剥奪は運営ログ（セキュリティ）に記録され、Discord にも通知
- **ログ**: **プレイヤー**（登録・ログイン・パスワード変更・引き継ぎコード・送金・通報・報告 / 意見案・購入）・**運営**（サイトを開いた・メッセージ・送金・処分・パスワード・引き継ぎコード・通報の処理・検知の確認・意見案の採用・自動返信と **DEV の更新**）・**セキュリティ**（開発者コード・運営権・アカウント削除・データの削除・バックアップ・不正な決済通知・管理コマンド）・**保管庫**（共有保管庫の分はファイル名を出さず、大きさと件数だけ）・**緊急**（緊急停止とその解除）に分けて、新しい順に 1 行で（何をしたか一目でわかる要約。分類ごとに絞り込めます）。タップすると日時（日本時間 / UTC・ミリ秒まで）・実行した人・対象・IP アドレス・ブラウザ / 端末・アクセス元・内容のすべて・前後のハッシュを表示。**記録は消すことも書き換えることもできません**（データベースが削除・変更を拒否し、各記録が前の記録のハッシュを持つので、裏で消されたり書き換えられたりするとログの上に「改ざんチェック」の異常が出ます。最新の記録の番号とハッシュはデータベースの外〔Cloudflare のオブジェクト自身の保存領域と Workers Logs〕にも控えているので、ログを最初から作り直したり後ろを切り取ったりしても見つかります。記録は操作と同じリクエストの中ですぐに書かれ、バックアップからの復元や時点への巻き戻しでも残ります）。**プレイヤーアクティビティ**（DEV11）の絞り込みで、プレイヤーの登録・アカウント削除・データの削除・処分とその解除・チャット停止・パスワードや引き継ぎコードの再設定・権限の変更・管理コマンドだけをまとめて見られます。**行をタップすると関連する場所が開きます**（プレイヤーの詳細・公式チャット・通報・検知・報告 / 意見案・運営者・アーカイブ・保管庫のその場所・セキュリティ・サーバー・課金。閲覧者は不具合を避けるため使えません）。記録のすべては右の **「詳細」**。**「AIに報告する文章」** で表示中のログ（最大 100 件）を、詳細では 1 件を、AI に貼り付けて相談できる文章にしてコピーできます（IP アドレス・端末・ブラウザ・コードなど人や機械を特定できる情報とハッシュは含めません）
- **課金**（開発者のアカウントだけに表示）: 開発者支援を購入した人が **返信待ち** として並びます（買ったもの・口数・金額の合計・ロイヤルコイン・購入日時）。返信を書いて「返信して一覧から消す」（送られる文面を確認してから送信）と、Ice Smoker公式から「【開発者からのメッセージ】〇〇様 … Two state 開発者 TAKU」として届き、**その人だけが一覧から消えます**（あとでまた購入すると、もう一度載ります）。「すべての注文」で状態（支払い待ち・完了・期限切れ・返金など）と返信を確認。上には決済の設定の状態（本番 / テスト / 停止中と足りない設定）、開発費のメーター、今月と累計の売上
- **保管庫**（運営者全員に表示）: **開発者専用保管庫**・**バックアップ**（開発者だけ）と、運営者どうしの **共有保管庫**・各運営者の **個人保管庫**（下）。開発者専用保管庫は開発者のアカウントだけが使え、**開発者コードを入れないときは閲覧のみ**（見る・開く・ダウンロード）。右上の **「編集する」** から開発者コードを入れると 30 分間変更でき、**「閉じる」** で閲覧のみに戻ります。3D モデルなどの大きなファイルを保存でき（**R2 につなぐと全体 50GB・1 ファイル 2000MB まで**。つなぐ前は全体 3GB〔無料プランは 1GB〕。上の「保管庫を R2 につなぐ」）、1MB（R2 では速さに合わせて 8MB か 16MB）ずつ、**そのままの形で**（base64 にせず）送って 1 つずつ SHA-256 Worker、`ops/ops-sw.js`・`ops/vault-upload.js`）で進み**、ファイルはこのブラウザ（IndexedDB）に預けられるので、**保管庫を閉じても、運営サイトのタブを閉じても続きます**（ブラウザがバックグラウンドの処理を止めたときは、次に運営サイトを開いたときに続きから。Chrome・Edge は Background Sync 秒）送り直します（その間は「すぐに送り直しています…（〇回目）」）。それでもだめならファイルごと **1 秒・3・10・30 秒後、そのあとは 1 分おきに何度でも**（通信が切れた・サーバーが混み合っている。止まっている間は「〇秒後に自動で再開」と表示し、サーバーがまた答えるようになったら・通信が戻ったら待たずにすぐ）、ほかのつまずきでも 15 秒・1 分・3 分・10 分後、そのあとは 10 分おきに自動で。ログインが切れたものはログインし直すと、許可が切れたものは開発者コードを入れると、すぐ続きを送ります（保管庫がいっぱい → 空きができしだい。削除されたファイルだけは止まったまま）。ログアウトすると、このブラウザに預けたログイン情報も消えます（次にログインすると続きから）。**保管庫の速さ**（上の「速さ」：**最速**〔はじめから〕・**高速**・**標準**。開発者だけが変えられ、運営者全員に反映・運営ログに記録）：最速は R2 で 16MB の部分を一度にたくさん（ブラウザ 1 つで合わせて 128MB   **画面（DEV11）**：上に **「アップロード」**・**「＋」**（フォルダを作る・**ファイルを作る**〔名前に拡張子を付けるとその種類に。例 memo.txt・main.py・index.html〕・メモを付けてアップロード）・**「リンク」**（保管庫全体のリンクを作る / 停止）。パソコンからファイルを **ドラッグ＆ドロップ** しても入れられます（保管庫の上なら今開いているフォルダへ、フォルダの上ならそのフォルダへ。編集できない保管庫ではお知らせだけ。パソコンのフォルダごとは入れられないので中のファイルを選びます）。一覧は 1 行に 1 アイテムで、**ファイルのアイコンをタップすると開きます**（フォルダは中へ、3D モデルは 3D で、画像・テキスト・プログラムはその場で表示、動画・音声は再生、APK などはダウンロード。ダブルクリックでも）。右の **💬**（コメントの数。押すとコメントの一覧と書き込み）・**「詳細」**（送信日時・大きさ・種類・SHA-256・リンク・メモ・バックアップ・3D の情報・中身の始め・AI のラベル）・**「⋯」**（開く・ダウンロード・名前を変更・移動・リンク・バックアップ・削除など、そのアイテムでできることすべて）。**右クリック（スマホは長押し）でも同じメニュー**が出ます。削除するときは必ず **「本当に削除しますか？」** と確認します。アイコンは仮のもの（`ops/icons/file.svg`・`apk.svg`・`folder.svg`。差し替えはこのファイルを置き換えるだけ）
  **APK・プログラムファイル**もそのまま入れられ（APK は専用のアイコン、プログラム〔js・ts・py・java・kt・c・cpp・cs・go・rs・php・sh・html・css・json など〕は「プログラム」としてアイコンに拡張子が付き、タップでコードを表示）、種類（3Dモデル・APK・プログラム・テキスト・画像・動画・音声・圧縮・その他）のタグ付き。どれも 1 件として数えます。各アイテムに **コメント**（1・3・7・30 日か期限なし）を残せ、**AI も AI 用リンクからコメントできます**（「AI」の印付きで表示。`POST /api/vault/ai { t, f, comment }`）。AI 用リンクでは期限までのコメントを AI も読めます（期限が過ぎても消えずに残り、AI には見えなくなります）
- **バックアップ**（保管庫・開発者だけ）: 開発者は **どの保管庫のどのアイテムでも**（共有保管庫・個人保管庫のものも、フォルダなら中のファイルすべて）「⋯」やチェックの「バックアップ」でサーバーにバックアップでき、バックアップしたものには **「バックアップ」のバッジ** が付きます（そのファイルが見える人には誰にでも表示）。バックアップしたファイルは、保管庫から削除されても消えずに **「バックアップ」**（保管庫を選ぶところ）に残り（バッジは「バックアップのみ」）、開発者が **元の場所に戻す** か **完全に削除** できます。ファイルをコピーせずにそのまま残すので、容量は増えません（削除されて「バックアップのみ」になったものは、その運営者の 1GB には数えません）。バックアップ・外す・戻す・完全な削除は運営ログに記録
- **個人保管庫**（運営者全員・DEV11）: 運営者 **1 人に 1 つ** の自分だけの保管庫です（保管庫タブを開くと最初に出ます）。**非公開**で、見られるのは本人と開発者だけ（開発者は閲覧のみ）。アップロード・フォルダ・ファイルを作る・コメント・名前の変更・移動・削除など、共有保管庫と同じことができます。容量は共有保管庫と合わせて 1 人 1GB（下）
- **共有保管庫**（運営者全員）: 運営者 **ふたりごとに 1 つ** ある保管庫です（例：Mod1 と Mod2、Mod1 と開発者）。保管庫タブを開くだけで使え（開発者コードは不要）、相手と共有したいファイルを置けます。**非公開**で、見られるのはそのふたりと開発者だけ（ほかの運営者には一覧にも出ません）。**開発者は運営者どうしの共有保管庫と各運営者の個人保管庫も閲覧できます**（中身を見る・ダウンロードするだけで、変更はできません。ページにもそう表示。バックアップはできます）。フォルダ・続きからのアップロード・テキスト・3D プレビュー・短期間メッセージ（どちらが書いたか付き）・チェックでの複数選択は開発者専用保管庫と同じで、各ファイルに送った人が出ます。容量は **開発者専用保管庫と共有**（同じ 50GB を使います）。相手の運営権が剥奪されると、残ったほうは見る・整理・削除はできますが、新しいファイルは入れられません。運営ログ（運営者全員が読めます）には、共有保管庫のファイル名やメッセージの文面は出ません（大きさと件数だけ）
- **容量の上限（1 人 1GB）**: 共有保管庫と個人保管庫で各運営者が使えるのは、**その人が送ったファイルの合計で 1 人 1GB まで**（個人保管庫とどの共有保管庫の分も合わせて。`VAULT_FREE_MB`）。超えるアップロードは止まり、**「容量を申請」**（希望する上限と理由）→ 開発者の保管庫タブに件数が出て（Discord にも通知）、開発者が **上限を決めて承認**（上限の設定は必須。希望より小さくても可）するか **見送り** ます。承認されると止まっていたアップロードは自動で続きから送られます。開発者は運営者ごとの使用量と上限を一覧でき、いつでも **上限を変更**（1GB に戻すことも）できます。開発者自身のファイルは上限に数えません。申請・取り下げ・承認・見送り・上限の変更はすべて運営ログ（保管庫）に記録
- **チェックで複数選択**（保管庫）: ファイルとフォルダの左上のチェックマークで選び、**Shift を押しながらで範囲選択**、「すべて選択」でそのフォルダの全件（全ページ）を選べます。選んでいる間は「N件を選択中」のバーが画面の上に残り、**移動**（フォルダごと）・**ダウンロード**（フォルダの中のファイルも 1 件ずつ）・**バックアップ**（開発者）・**削除**（ファイルは完全に削除〔バックアップしたものはバックアップに残る〕、フォルダは中身をひとつ上へ）をまとめてできます（閲覧のみの保管庫ではダウンロードだけ）
- スマホでは最初のタップで **全画面・横向き** になります（Android の Chrome。ホーム画面に追加すると最初から横向き全画面）。横向きにできない端末で縦に持っているときは、サイト全体が横向きに回転して表示されます

**パスワードは表示できません。** 安全のため元に戻せない形（ハッシュ）でだけ保存しているので、運営者にもデータベースにも元のパスワードはありません。
忘れた人には新しいパスワードを設定してください。引き継ぎコードは暗号化（HMAC-SHA256 による暗号化と改ざん検知、鍵はサーバーの秘密値から作成）して保存しているので一覧で見られます。
この仕組みを入れる前に発行されたコードは「未取得（再発行で表示）」と出ます（本人が「引き継ぎコード発行」をするか、運営が再発行すると表示されます）。

### 運営の画面を見る機能（状態転送方式）

運営サイトのプレイヤー一覧の **「見る」** で、オンラインのプレイヤーのゲーム画面をリアルタイムで見られます。実装は `server/core/opswatch.js`（サーバー）・`js/net/watchfeed.js`（プレイヤーのゲーム）・`js/net/watchcrypto.js`（暗号）・`ops/watch.js`（運営サイトの窓）、設計の詳細は [`docs/ops-screen-view.md`](docs/ops-screen-view.md)。

**映像ではなく「ゲームの状態」を送ります。** 運営の画面は H.264 の映像にせず、ゲームが持っている状態（どの画面か・残高・ベット・どのリールが回っているか・止まった絵柄・当たりの金額）だけを送り、運営サイト側で描き直します。ブラウザが映像にできるのは canvas 1 枚（`captureStream`）か、本人の許可の表示が出る画面共有だけで、メニューやチャットなど DOM の画面は写せず、3D の画面も別の扱いが要ります。映像にすると 300kbps で 1 時間あたり約 135MB かかります。状態なら **1 フレーム約 260 バイト** で、変わったときだけ（20fps なら 1 秒に最大 20 回）、変わらなければ 2 秒に 1 回の心拍だけ。**実測（本物のゲームを 540P・20fps で見ながらスピンし続けて）は平均 0.3 KB/秒（約 2.5kbps、300kbps の約 1/120）**、毎フレーム変わり続けるという起こりえない最悪でも約 42kbps です。3D の画面も「どの画面か」を送るだけで済みます。遅れは、ゲームが状態を見に行く間隔（20fps なら最大 50ms、10fps なら最大 100ms）に通信 1 回分を足したものです（同じマシンでの実測は、暗号化してから運営サイトで開くまで中央値 5ms・95% が 14ms 以内）。

| 指定 | 実装 |
| --- | --- |
| 見るボタンを押してから送る | サーバーが「見る」の合図をそのプレイヤーのゲームにだけ送り、ゲームはそのときだけ状態を送ります。終わると止まります |
| 画質 540P / 480P / 360P / 240P ・ 20 / 15 / 10 fps | 運営サイト側の描き直しの高さ（540・480・360・240）と、ゲームが状態を見に行く回数（20・15・10 回/秒）。窓の上で切り替えられ、プレイヤー側の回数もそれに合わせます |
| 300kbps（一律） | サーバーが 1 回の監視を **毎秒 37,500 バイト（300kbps）で頭打ち** にします（超えたフレームは捨てる）。1 フレームは 6,000 文字まで |
| 音声は送らない | 音声・カメラ・マイクにはいっさい触れません（効果音も送りません） |
| アニメーション超簡略化・演出オフ | 描き直しは演出なし（リールが回るのと数字の表示だけ）。変わらないときは再描画もしません |
| 通信量の小さい文字表示 | 窓の下に「通信（今の毎秒）・今回の合計・累計」を小さい文字で（サーバーが数えた値。1 秒ごと） |
| 1 回最大 30 分・画面にタイマーなし | サーバーが 30 分で終了します。窓には残り時間も経過時間も出ません（終わったときだけ理由を表示） |
| 操作を乗っ取れない | 運営側からプレイヤーのゲームへ送れるのは「画質・fps の変更」と「止める」だけで、タップ・キー・命令にあたるメッセージはどちら向きにもありません（`server/test/opswatch.test.js` が確認） |
| 通信を強固に | 下の「安全の仕組み」 |
| 緊急時は強制終了 | 緊急停止・ロックダウン・攻撃を検知（セキュリティシールドの限界の半分）・運営権の剥奪・プレイヤーの処分・今月の使用量が上限に達したとき、すべての監視をその場で終了し、Discord に 【危険】 で報告します |
| ログ | 開始と終了を **改ざん検知つきの運営ログ（セキュリティ）** に記録（見た人・見られた人・開始と終了の時刻・時間・通信量（合計・平均・捨てたフレーム）・画質・終わり方・その運営者の累計）。専用の表 `ops_watch_log` にも残り、サーバーの再起動で途切れた監視も次の起動で閉じて記録します |
| 見ながらできること | 簡易メッセージ（Ice Smoker公式から。定型文 5 つか 200 文字まで）・アクセス禁止（1 週間）・BAN（30 日）・永久BAN（確認ダイアログつき）・★お気に入り |
| 本人に知らせない | 見ている間、プレイヤーの画面は 1 要素も変わりません（実ブラウザで比較して確認）。ただしルールには「運営がプレイ中のゲームの状態を確認することがある」と書いてあります |

**安全の仕組み。** ① 1 回の監視ごとに **新しい鍵**（ECDH P-256 → HKDF-SHA256 → AES-256-GCM）をプレイヤーのゲームと運営サイトのページで作り、公開鍵だけをサーバー経由で交換します。フレームは **封をしたまま** サーバーを通り、サーバーは中身を読めません（運営サイトの別のタブや別の運営者にも読めません）。② カウンターは増えるだけで、監視の ID・鍵の世代・カウンターが認証の対象なので、再送・並べ替え・別の監視への流用・書き換えはすべて開けません。③ **プレイヤーのゲームは改造されうるので、運営サイトは届いたものを疑います**：数値は決まった範囲に丸め、文字は自分で決めた言葉だけを描き、`innerHTML` は使いません。④ 開始は運営者だけ（閲覧者は不可）・同時に 3 件まで・1 人の運営者は同時に 1 つ・1 人のプレイヤーは同時に 1 人まで・開発者のアカウントは開発者以外は見られない・開始と鍵の交換には運営サイトのリアルタイム接続が必要。⑤ 運営サイトの秘密鍵はそのタブのメモリだけで、取り出せない形で持ちます。

**プレイヤーのゲームが送らないもの。** 映像・音声・カメラ・マイク・位置・端末の情報・入力した文字・チャットの中身・パスワード・決済の情報。送るのは、画面の種類（スロット・メニュー・クエストなど。メニューの中のどのチャットかも送りません）・トークン / $ / ロイヤルコインの数・ベット・リールの回転と止まった絵柄・当たりの金額と等級・コンボ数だけです。

**実ブラウザでの確認**（`node tools/check_ops_watch.cjs`、Playwright が必要）：本物のゲームのページを開いたプレイヤーと本物の運営サイトで、見る → スピンを運営の窓が追う → 画質の切り替え → 簡易メッセージ → ★ → 終了で、プレイヤーの画面に新しい表示が出ないこと・窓にタイマーがないことまで見ます。友達の観戦の画質は `node tools/check_friend_watch_quality.cjs`（60.7 → 24.8 fps、460P でリールの絵が半分の幅）。

### 管理コマンド

`ADMIN_TOKEN` を設定したあと、Node.js の入ったパソコンから実行します。

```sh
export ADMIN_TOKEN=設定した合言葉
URL=https://blockbuster-reels.あなたのアカウント名.workers.dev
node server/node/admin-cli.js --remote $URL stats                 # 全体の数字
node server/node/admin-cli.js --remote $URL users [検索語]        # プレイヤー一覧
node server/node/admin-cli.js --remote $URL show たけし           # 1 人の詳細
node server/node/admin-cli.js --remote $URL ban たけし            # 永久BAN（unban で解除。期限付きは運営サイトから）
node server/node/admin-cli.js --remote $URL grant たけし dollars 100000   # 残高を増減（マイナスで減らす）
node server/node/admin-cli.js --remote $URL rename たけし たけし2  # 名前の変更
node server/node/admin-cli.js --remote $URL recovery たけし       # 引き継ぎコードを再発行（本人確認のうえで）
node server/node/admin-cli.js --remote $URL password たけし 新しいパスワード  # パスワードを設定し直す（本人確認のうえで）
node server/node/admin-cli.js --remote $URL backup backup.json    # 全データをファイルに保存
node server/node/admin-cli.js --remote $URL quota                 # 今日のリクエスト数・送信量（DAILY_* を設定した場合）
```

- もしもの時の巻き戻し: Cloudflare はデータベースの過去 30 日分を保持しています。
  `node server/node/admin-cli.js --remote $URL restore-time 2026-10-17T12:00:00Z` でその時点の状態に戻せます（通常は不要です）。
  運営ログだけは巻き戻らず、そのまま残ります（コマンドが巻き戻しの前に取り出して、あとで戻します）。
- 管理コマンドで変更したこと（BAN・残高の変更・名前の変更・再発行・パスワード・ログイン解除・削除・バックアップ・復元・巻き戻し）も、運営サイトのログに残ります。

- スマホ通知: ホーム画面に追加した Web アプリ（iPhone は iOS 16.4 以降）とブラウザは、ゲームを閉じていても通知が届きます（Web Push）。Android アプリは、アプリがバックグラウンドで動いている間にアプリ自身が通知します（アプリを完全に終了しているときは届きません。届くようにするには Firebase の設定が別に必要です）。
- Android アプリは Google Play を通さない配布なので、ダウンロードやインストールのときに Android の注意が表示されます（「ダウンロード」「この提供元のアプリを許可」で進めます）。
  Google はストア外のアプリにも開発者登録を求める方針を発表しており、国ごとに順次始まります。その場合でも Chrome の「アプリをインストール」は使えます。

### Android アプリ（APK）を作る（最初に 1 回だけ）

アプリは GitHub が無料で自動作成し、ゲームのサイト（`/download/`）に置きます。

1. **署名の合言葉を登録する**: GitHub のこのリポジトリ → Settings → Secrets and variables → Actions →
   New repository secret → Name に `APP_SIGNING_KEY`、Secret に好きな長い文字列（30 文字以上。パスワード生成サイトで作ったもので OK）→ Add secret
   - **一度決めたら変えないでください。** アプリの更新は同じ合言葉で作ったアプリにしかできません。
2. **アプリを作る**: GitHub の **Actions** タブ →「Android app」→「Run workflow」→「Run workflow」
   - ゲームの URL（`https://blockbuster-reels.sc8z-35a.workers.dev/`）は `app/app-url.txt` に記入済みです。URL が変わったときはこのファイルを書き換えると作り直されます
3. 3〜5 分でアプリができ、ゲームのサイトに自動で置かれます（Cloudflare の自動デプロイ後に使えます）。
   起動画面の「アプリで遊ぶ」→「アプリをダウンロード」から入れられます
   - 合言葉が未登録のうちはアプリは作られるだけで公開されません（Actions の結果に案内が出ます）

### アップデートの仕組み

- **ゲームの中身**（画面・機能・バランスなど）は、サーバーを更新するだけで全員に届きます（ブラウザ・iPhone のホーム画面アプリ・Android アプリ共通）。

## ルール（ゲーム内「ルール」タブと同じ）

- 「SPIN」をタップして開始します。
- スピンごとにベットが引かれます。賞金はベットと、中央ラインにそろったシンボルの種類と数で決まります（並び順は問いません）。
- 当たりの組み合わせが複数あれば、報酬は加算されます。
- スピン中に終了すると、ベットは戻りません。
- 1 日の購入上限: 10,000,000 スピントークン（毎日 00:00 UTC にリセット）。
- スピンは **1 秒に 1 回まで**（サーバーが数えます。リールの回転は 1 秒以上かかるので、ふつうに遊んでいて引っかかることはありません）。
- **プレイの確認**：不正やトラブルを防ぐため、運営がプレイ中のゲームの状態（画面の種類・残高・ベット・リールなど）を確認することがあります（運営サイトの「見る」。下の「運営の画面を見る機能」）。映像・音声・カメラ・入力した文字・チャットの内容は取得しません。見られていることをその場でプレイヤーに知らせることはしません。
- 1 スピントークン = 10 $。「トークンを入手」で $ と交換、「トークンを交換」で $ に戻せます。毎日 1 回、無料トークン（1,000）を受け取れます。
- **サブアカウントの禁止**：ひとりで 2 つ目以降のアカウントを作る・使うことは禁止です。違反はアクセス禁止・BAN の対象です（登録画面にも表示）。

### 当たり演出

WIN・BIG WIN・SUPER BIG WIN の文字は **回転する 3D の文字**（`img/3d/*.glb`、three.js で表示）。正面を向いたときはゆっくり、裏側はすばやく回ります。WIN はリールの上に 1.6 秒、BIG WIN は回転しながら叩きつけられ、SUPER BIG WIN はカウント途中で 3D の SUPER BIG WIN に切り替わります。モデルはゲームが始まったあとにオンラインのときだけ裏で読み込み（モデル 4 つで約 3.2 MB と three.js 約 0.8 MB、一度読めばキャッシュ）、読み込むまで・WebGL のない端末・演出設定の「3Dの当たり文字」がオフ・動きが重い端末（自動で判定）では従来の文字で表示します。**77777（7 が 5 つ）のときだけ** は SUPER BIG WIN の代わりに虹色の **ULTRA BIG WIN**（3D、従来の文字では虹色の「ULTRA」）。

リールの回転は途中で止められません。BIG WIN 以上の演出中は画面をタップするとカウントを飛ばせます。あと 1 つで 20 倍以上になる場面では残りのリールが減速して炎に包まれ、「チャンス！」「激アツ！！」と稲妻の「リーチ演出」が入ります。

### DEV13：追加クエストと収益の回収待ち

- クエストを35個追加（デイリー16 STEP・特別19 STEP）。既存のSTEP表示・レア度・達成時のPRO／ULTRA抽選に対応。今後のDev Newsでも追加数にまとめて記載します。
- レベル・VIPの到達済み条件と特別クエストの累計カジノ獲得額は既存データから反映。車購入は追加後の購入成功を集計し、贈与・失敗は数えません。
- バイトと車の貸し出しは回収待ちで収益が止まり、受け取り時から再開。待機中に貸し出しを止めた車は自動再開しません。画面には上限額・上限の説明を表示しません。


### 金の生る木の3D対応（指定素材の一部は未取り込み）

- 添付の種、第1・第2段階、競り用プレビューの木を `img/3d/tree/` に軽量化して取り込み済み。種と競り用の木はゆっくり回転し、木の画面は360度回転・2本指／ホイール・＋／−でズームできます。2Dの代替画像も同じ3Dから描画しています。
- **第3〜9段階と土の添付GLBは32MiB転送上限を超えて取得できていません。** この7段階は既存の2D画像を維持し、取得済みの段階の土は仮の3D円盤です。全9段階の差し替え・指定された土との合成は未完了です。
- 不足モデルを取得後、`tools/3d/source/tree-stage-3.glb` 〜 `tree-stage-9.glb` と `tree-soil.glb` に置いて `sh tools/3d/build.sh` を実行します（取得済みの原本は `tree-stage-1.glb`、`tree-stage-2.glb`、`tree-seed.glb`、`tree-preview.glb`）。生成済みファイルを検出する `tools/3d/tree-manifest.mjs` が利用可能な段階だけを登録します。
- 取得済みの3D段階では、投入成功ごとに新規作成の肥料袋を横から投げます。cannon-esで重力・反発・摩擦・回転・袋同士の衝突を計算。幹・樹冠・土には形状に合わせた簡易コライダーを設定し、袋ごとの8秒タイマーでメッシュと剛体を除去します。再入金や描画更新で既存のタイマーは延長されません。
- 9段階の基本生産量は毎秒$5〜$14。周期とSUPERの収穫倍率は従来どおり。期限後は画面を「生産停止中」・毎秒0に切り替え、APIの `activeRate` も0になります。
- 保管庫は完成済み3Dファイルの一覧にプレビューを自動表示します。軽量版を優先し、見えているモデルだけ読み込み、複数のプレビューでWebGLレンダラーを共用します。スクロールアウト・タブ移動・ログアウト時に描画リソースを解放します。
- 肥料の原本生成は `tools/3d/make-fertilizer.mjs`、物理エンジンの入口は `tools/3d/tree-physics-entry.js`。cannon-esのMITライセンスは `js/vendor/cannon-es.LICENSE.txt` に同梱しています。
