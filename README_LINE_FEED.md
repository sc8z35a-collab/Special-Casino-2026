# LINE公開配信とガチャ

既存のMessaging APIチャネルと署名付き `POST /api/line/webhook` を使います。
`LINE_FEED_ENABLED=true` で公開配信モード（Cloudflareの既定設定）。Nodeでは同じ環境変数で有効化します。
チャネルのシークレット `LINE_CHANNEL_SECRET` と `LINE_CHANNEL_ACCESS_TOKEN` はホストのシークレットにのみ設定します。未設定なら外部送信しません。

## LINE側の設定

1. Webhookを有効化し、URLを `https://ゲームのホスト/api/line/webhook` に設定。
2. LINE Developersでグループ・複数人トークへの参加を許可。
3. Official Account Managerの自動応答・あいさつ・リッチメニューを無効化。
4. Nodeでは `PUBLIC_URL` にゲームの公開HTTPS URLを設定。Cloudflareでは信頼できるリクエストのホストを保存して使います。独自ドメインを優先する場合は同じ変数を明示。
5. 友だち追加・グループへの参加で登録。既存トークは次の通常メッセージで無言で初期登録。既知の送信先は `LINE_FEED_TO` にU/C/Rから始まるIDをカンマ区切りでも設定できます。ブロック・退室後は停止し、古いイベントでは復活しません。

公開配信モードでは**すべてのコマンドへの返信を止めます**。従来の「パスキー」「ID」「ヘルプ」も返信しません。運営用パスキーは既存のDiscord `/passkey` または認証アプリによる非常口を使います。運営者向けの警告は従来の限定送信先にのみ届き、公開グループには流れません。

## 配信内容

- 日本時間毎日9時：テキストは **「今日の一枚」だけ**と写真1枚。`LINE_FEED_HOUR_JST`（0〜23）で時刻変更可能。壁紙アプリの `ops/assets/wallpapers.json` と標準・予備の計67枚が対象です。全写真を1回ずつ選び終えて1サイクル、境界でも連続して同じ写真を選びません。配信先のない日は進めません。
- 原画像の縦横解像度を保ったJPEGを用意し、プレビューだけ320px以下にします。配信時の画像取得・再圧縮・base64化はありません。Static AssetsのURLは**圧縮済みバイトのハッシュ**で、再圧縮時も古いキャッシュと混ざりません。画像変更後は `python3 tools/build_line_wallpapers.py`（Pillowが必要）を実行し、JPEGと `server/core/line-wallpapers.json` をコミット。写真のサイクル識別子は原画像のピクセルから求めるため、再圧縮だけでは重複判定は変わりません。テストが壁紙アプリとの整合・ファイルサイズ・JPEG解像度を確認します。
- 月曜9時：カジノコインとロイヤルコインを別々に週1回。カジノコインは**週の抽選10%で20,000枚**、残り90%は500〜10,000枚の整数から均等。ロイヤルコインは2〜6枚から均等。結果は週ごとに保存し、全配信先で同じです。文言は通貨名と枚数だけ。
- 報酬カード全体をタップするとゲームを開き、ログイン後、ゲーム内の「受け取る」で加算します。**各ゲームアカウント・各通貨・各週に1回**。複数グループ・転送・二重タップで重複しません。次の月曜の配信時刻で期限切れです。LINEからゲームの操作や残高確認はできません。LINEアカウントとの紐付けも不要です。
- デプロイ版が変わると **「DEV13のバージョン＜デプロイ版ID＞にアップデートされました。」** の1文だけを配信。DEV番号は最新版から読みます。初回有効化時は現在版を基準として保存し、過去の更新は通知しません。NodeではゲームのビルドIDを使います。

SQLiteに日付別配信・送信先別UUID・週次抽選・受取台帳を保存します。再起動・同時実行・通信失敗でも同じ `X-Line-Retry-Key` を再利用し、LINEが受理済みの再送は確認ヘッダー付き409で完了にします。23時間を超えて再試行せず、古い写真の翌日埋め合わせも行いません。既存のDurable Objectアラームに時刻を統合し、失敗時は間隔を伸ばし、429では1時間待ちます。送信はリースを保存してから最大4件ずつ並行し、送信先を増やしても接続数は増え続けません。登録済みのチャットの通常メッセージではアラームを再設定しません。配信先がない間も毎分起床しません。ゲーム側の定期ポーリングは不要です。

LINE公式の[画像仕様](https://developers.line.biz/ja/reference/messaging-api/#image-message)と[再試行仕様](https://developers.line.biz/ja/docs/messaging-api/retrying-api-request/)に従います。ブロック・グループ参加禁止・月間送信枠超過・LINEの障害時には配達を保証できません。グループはメンバー人数に応じて枠を消費し、写真配信はテキスト＋画像です。必要な送信枠はLINE側で確保してください。LINEアプリ内の表示・保存時の画質処理はLINE側の仕様です。

## ガチャ

「詳細」→「ガチャ」から開きます。通常ガチャは削除し、**レア・レジェンダリー・シークレットの3種類**です。旧 `kind: normal` のAPI要求も拒否します。

**1回3枠の独立抽選、3連9枠、10連30枠**です。同じ報酬も出ます。ゲーム内のお金で支払い、3連10%引き・10連25%引きは常時適用します。古い10連割引や期間セールの値引きは重ねません。

| 種類 | 単発（3枠） | 3連・10%引き（9枠） | 10連・25%引き（30枠） |
|---|---:|---:|---:|
| レア | 3,500,000 | 9,450,000 | 26,250,000 |
| レジェンダリー | 15,000,000 | 40,500,000 | 112,500,000 |
| シークレット | 30,000,000 | 81,000,000 | 225,000,000 |

**リリース記念セール**：サーバーがこの版で最初に動いた時から **100 時間だけ**、シークレットガチャが **1 連 10,000,000**（3 連 27,000,000・10 連 75,000,000）になります（開始時刻は `meta` の `gacha_release_sale` に一度だけ記録され、再起動しても延びません。`GACHA.releaseSale` が種類・価格・時間）。ガチャ画面ではシークレットに「リリースセール」の画像と残り時間を表示し、元の価格に取り消し線を引きます。見積もりと請求は同じ価格（セールの終わった後に古い見積もりで引くと `price_changed`）。

提供された青・金・紫のサムネイル、1連・3連・10連、10%OFF・25%OFF、確率ボタンを使用します。新しい青紫の背景を使い、戻るボタンとYES/NOは既存の共通コントロールです。引くボタン→赤い大きな角丸の最終確認（背後を強くぼかす）→YESの順で、YESを押すまで抽選APIを呼びません。確率ボタンの別画面には「アイテム」「確率」の2列だけを表示します。

演出は約0.9秒のCSSによる揺れ・カプセル・結果カードで、常時3D描画は行いません。サーバーで決済・付与済みの結果のみを表示し、スキップ・演出オフ・画面を隠した場合はすぐに結果を表示します。単発3枚、3連9枚、10連30枚の報酬画像は内蔵の車・コイン・ガレージ・クエスト・VIP・種・木を使用します。ポルシェ固有の画像/モデルは内蔵されていないため、その車だけ既存の汎用車アイコンに車名を併記します。画像はWebP化し、ガチャ素材12枚全体で**75,918バイト**です。表示サイズに合わせて元の提供画像から縮小・圧縮し、透過を維持し、アップロード原本には手を加えません。素材の更新は `python3 tools/art/import_gacha.py アップロード元フォルダ`。

通信は共通APIを通し、Cloudflareでは最新のWebSocket経路をそのまま利用します。接続が切れて結果が不明な購入をHTTPで自動再送しません。LINEの受取は既存のHTTP限定経路を保ち、受取台帳で重複を防ぎます。運営画面の一括取得・差分応答、スピンの圧縮、TURBO VOICE、コードのハッシュ付きキャッシュには変更を加えません。

ガチャのボタン・サムネイルとイベントリスナーは初回表示時に作り、以後は値と状態だけ更新します。確率表は共有ルールとサーバーから受け取った時刻で算出し、開くたびの通信はありません。結果画像は遅延読み込みします。抽選表は購入ごとに1回だけ作り、暗号学的乱数は128個ずつ取得し、バッファの各要素を1回だけ消費します。所持品は残高表示用に読み取ったものを共有し、固定価格を要求のたびに計算し直しません。

最適化前 `9322c2d` との比較は [docs/line-gacha-optimization.json](docs/line-gacha-optimization.json) に保存しています。ガチャ画像は876,618→75,918バイト（91.34%削減）、LINE画像134枚は6,934,143→3,843,258バイト（44.57%削減、67枚すべて同じ解像度・同じサイクル識別子）です。抽選計算だけの計測では10連10,000回・7試行の中央値が1,222→190msでした。900通りの乱数列・種類・連数・キャンペーンの組合せで結果が一致しています。この数字は通信・DB・演出を含むゲーム全体の速度ではありません。再計測は `node tools/measure_gacha_rules.cjs 9322c2d`。

`server/test/socketapi.test.js` がガチャの3/9/30枠・見積金額・HTTPとWebSocket間の残高一致、LINE受取のHTTPへの引継ぎと一度限りの加算を確認します。`server/test/line-feed-migration.test.js` は既存DBへの追加移行でアカウント・通貨・セッション・鍵を保つことを確認します。本番の読み取り検査 `python3 tools/check_production.py` はビルドID・API・ガチャ素材・LINE壁紙を確認し、購入や配信は行いません。

実ブラウザの追加検査は `node tools/check_gacha_optimization.cjs`。画面構築の再利用・追加通信なしの確率表・キャンペーン切替・9価格・3/9/30枠・二重課金防止・スマホ確認画面を、使い捨てのローカルDBで検証します。PlaywrightとChromiumが必要です。

以下は通常時の1枠あたりの確率です。ロットコインは各範囲内で1,000刻み、ロイヤルコインは1枚刻みの均等抽選です。

| 報酬 | レア | レジェンダリー | シークレット |
|---|---|---|---|
| ロットコイン | 10,000〜25,000個：30% | 10,000〜40,000個：10% | 100,000〜300,000個：10% |
| ロイヤルコイン | 8〜12枚：20% | 20〜32枚：10% | 30〜60枚：8% |
| ロイヤルコイン大量枠 | — | — | 90〜120枚：19% |
| ガレージコイン | 1枚：10% | 1枚：20% | 4枚：8% |
| リセットチケット | 1枚：15% | 2枚：15% | 3枚：10% |
| VIP1週間券 | 1枚：14% | 1枚：24% | 1枚：24% |
| オンヴォーロ専用枠 | 7% | 5% | — |
| ポルシェクイヤスパイダー専用枠 | 2% | 4% | — |
| ランダムな車 | 1.985% | 10.995% | 20% |
| 金の生る木の種 | 1個：0.01% | 1個：1% | 1個：1% |
| 成長済みノーマルの金の生る木 | 1本：0.005% | 1本：0.005% | — |
| **合計** | **100%** | **100%** | **100%** |

「ランダムな車」は全種類とも12車種から均等（各1/12）で、専用枠の2車種も含みます。ガレージコイン4枚は枠を4つ、リセットチケット3枚は5時間クエスト券を3枚増やします。シークレットの2つのロイヤルコイン枠は別々に抽選します。

既存の確率アップは週1回・24時間で、各ガチャの車の枠が**1.5倍**になります。それ以外を同比率で減らし、合計100%を維持します。車の合計はレア10.985%→16.4775%、レジェンダリー19.995%→29.9925%、シークレット20%→30%です。

従来の週1回・24時間のおまけ期間は維持します。各回80%でロイヤルコインのおまけ（無条件で4枚71.2%、12〜16枚計8%、20〜32枚計0.8%、なし20%）が付き、結果の上に合計を表示します。これは3/9/30枠とは別のおまけです。連数によって各枠の確率は変わりません。ガレージや木の上限に収まらない抽選は支払いごと取り消します。種・VIP券はガチャ画面から使えます。

アイコンの追加圧縮は140枚で1,145,577→436,631バイト（61.89%削減）。背景・壁紙・アニメーションシート・枠は対象外で、PWA/Android用PNGの指定寸法は維持します。記録は `docs/icons-compression.json`、再生成は `python3 tools/art/compress_icons.py --ref 9322c2d`。運営画面の描画・監視の最適化は [docs/ops-optimization.md](docs/ops-optimization.md) を参照してください。
