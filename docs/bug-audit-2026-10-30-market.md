## 修正した14項目

| 問題 | 影響と修正 |
|---|---|
| アバター購入後の進捗保存失敗で、代金と所有状態だけが確定する | 購入と購入後の進捗処理を同じトランザクションへ入れる。失敗時は代金・所有アイコン・装着中アイコンを保持する |
| ショップ購入後の進捗保存失敗で、エラーでも商品を購入済みになる | 引落し・在庫・購入後の進捗処理をまとめて確定する。再試行で意図しない追加購入にならない |
| ガレージ拡張後の進捗保存失敗で、エラーでも枠と引落しが残る | 枠の拡張と購入後の進捗処理をまとめて確定する |
| 新車購入後の進捗保存失敗で、購入・VIP EXPだけが残る | 引落し、車の所有権、VIP EXP、関連するバイト代精算、車購入クエストを同じ確定範囲にする |
| フレンドからの車購入がエラーでも確定する | 進捗保存に失敗すると、購入代金・所有権移転・売却カード・ライブ通知が先に確定していた。購入と進捗をまとめ、失敗時は出品中のまま再試行できるようにする。クエスト達成によるVIP昇格でバイト代が残高上限を超える実例も検査する |
| フルーツの送信が進捗保存失敗でも成立する | 送受信者の残高・送金記録・フルーツ進捗を同じトランザクションにする。失敗時はフルーツ演出や決済通知も送らない |
| バイト代の受取・退職が進捗保存失敗でも確定する | 給与・精算時刻・勤務状態・給与クエストをまとめて確定する。失敗時は未精算分と勤務状態を保持し、修復後に一回だけ支払う。開始処理も同じ確定範囲へ整理する |
| VIP購入・無料体験が、給与や実績の保存失敗でも確定する | ロイヤルコイン、期限、PRO／ULTRA区間、無料体験の使用状態、給与精算、関連する進捗をまとめて確定する。給与がない場合のVIP実績保存失敗でも購入だけを残さない |
| 車一覧の遅い応答で出品先が前の相手へ戻る | 一覧要求を開始した操作を確認し、最後に開いた相手の一覧だけを反映する |
| 閉じた画面が、車一覧の読込完了後に再表示される | 既存のモーダル世代を読み取る小さな共通メソッドを加え、表示前に閉じられた要求も無効化する。別アカウントへ移った場合も開かない |
| 古い出品処理が次の出品画面へ作用する | 閉じた画面の送信中状態を解除する。古い成功・エラーは、新しい画面を閉じたりボタンを解除したりしない。新しい画面へのメッセージ・通知も出さない |
| 古い数値入力画面が、次に選んだ車の価格を変える | 数値入力の開始時の操作とモーダルを確認する。閉じた後に届く価格ボタンのイベントも安全に無視する |
| 古いプレゼント送信の結果が、別の宛先や送信中状態へ作用する | 宛先を送信開始時に固定し、完了時に同じ画面か確認する。古い成功で次の画面を閉じたり、古いエラーで新しい送信を二重実行できる状態にしたりしない |
| 古いプレゼント送信・受取の応答が、切替後の口座へ反映される | 口座の切替時に画面と受取処理を無効化する。APIの成功が既に確定していても、待機中の旧コールバックは新しい口座の残高・メッセージ・演出へ作用できない。同じ口座のプロフィール更新では通常の操作を維持する |
