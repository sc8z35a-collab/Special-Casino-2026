# 3Dプレビューの軽量化

`js/ui/tree.js` の `marketsView()` は `BR.tree3d.icon()` を通じて、競りに入る前の
選択カードだけに次の2ファイルを使います。呼び出し元と `js/render/tree3d.js`、
`js/art/tree-models.js` を確認し、プレビュー専用の2ファイルに限定しました。

| ファイル | 変更前 bytes | 変更後 bytes | 三角形数 前→後 | テクスチャ最大辺 前→後 |
| --- | ---: | ---: | ---: | ---: |
| `img/3d/tree/preview.glb` | 1,483,556 | 253,216 | 205,440→8,000 | 1024→512px |
| `img/3d/tree/seed.glb` | 476,376 | 204,784 | 66,024→8,000 | 768→512px |

`tree/stage-1.glb`（591,708 bytes）と `tree/stage-2.glb`（686,840 bytes）は
小さなタブのプレビューにも使いますが、育成画面本体と共用するため変更しません。
`tree/fertilizer.glb` は操作中の肥料、`auction/` は競り会場・人物・出品物、
`cars/`・`studio/`・`garage/` は車の鑑賞・操作画面、当たり文字と `effects-lite/` は
実際のゲーム演出です。これらのデータは全て変更前のハッシュと一致しています。

## 再生成

`node tools/3d/compress-previews.cjs` は、既に配信している `ops/vault3d.js` 内の
meshoptimizer 0.22の簡略化処理と `js/vendor/three-bundle.js` のデコーダーを使います。
新しいnpmパッケージの導入は不要です。画像は既存の `tools/art/` と同じPillow環境で
最大512pxのWebPにします。頂点属性は量子化表現を保持し、不要頂点を除いたGLBを出力します。
結果は300,000 bytes以内であることを確認してから置換します。
既に予算内の出力は再圧縮せず、繰り返し実行しても同一バイト列を保持します。

簡略化器の非公開エクスポートを使うため、保管庫バンドルのメモリ上のコピーから
インスタンスを取り出します。配信中のバンドルは変更しません。
バンドルの構造が変わった場合はアサーションで停止するので、その時点で確認してください。
`tools/3d/build.sh` も最終処理として同じ圧縮を呼び出します。
配信ファイルを変更したら従来どおり `node tools/stamp.mjs` を実行します。

## 検証

`tools/3d/check-previews.html` をリポジトリのルートを配信するHTTPサーバーで開くと、
ゲームと同じ `GLTFLoader` / `MeshoptDecoder` とブラウザの画像デコーダーで検証できます。
このチェックはWebGLを必要としません。

2026-10-25（日本時間）、実ブラウザで両GLBの読み込み、各3テクスチャのデコード、
各8,000三角形、最大512px、300,000 bytes以内を確認しました。
実際のゲームの「金の生る木」画面も開きましたが、検証用ブラウザがWebGLを無効にしており、
3D描画の見た目は確認できませんでした。これはモデルの読み込み検証とは区別しています。
本番データ・Wranglerのバインディング・DBスキーマには変更を加えていません。
