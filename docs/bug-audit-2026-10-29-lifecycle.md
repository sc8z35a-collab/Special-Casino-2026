基点は PR #56 を取り込んだ main `c9b911d794591f7f339578c6bb4521c8f0cf9300`。前回の修正に続き、初回読込中の連続操作と、終了後に届く非同期処理を調査した。新機能、画面デザイン、価格・確率・配当、サーバーの権限や保存データは変更していない。

## 再現できた問題と修正

| 項目 | 再現条件・影響 | 修正 |
|---|---|---|
| 確認操作の待機が残る | 最初のCSSを読む前に閉じる、別の確認へ置き換える、読込に失敗する。画面がまだ非表示だと確認結果が確定せず、呼び出した操作が待ち続ける。Escapeでも保留中の確認を取り消せない | 表示前でも取り消し結果を返し、失敗時にも解除する。取り消した処理の後着エラーは表示しない。最後の確認だけを承認できる |
| 遅い画面が後の操作を上書きする | 車・ガチャなどの初回読込中に別の機能を選ぶ。各ローダーが独立しており、最後に選んだ機能ではなく、ダウンロードが終わった順に画面を開く | 通常画面と任意読込する画面・コントローラーで選択順を共有する。古い要求は開かず、古い失敗通知も出さない。成功した読込・初期化はキャッシュし、再選択時に再取得しない。読込失敗の表示は再試行できる案内へ統一 |
| 終了済みの通話接続を処理する | 旧接続の音声イベントで音声要素が再作成される。同じ通話の接続を交換した後も、旧接続のICE情報やSDP処理の完了が反映される | 通話と接続オブジェクトの両方を照合する。送受信イベント・SDP処理・送信キューを確認し、終了時にハンドラーを外す。全通話終了と個別接続の解放を同じ処理へ集約 |
| 2時間制限が端末時計に依存する | 時計を戻した後に期限タイマーが来ると、期限前と判定して終了せず、再予約もしない。反対に、旧期限の遅延処理が新しい通話を終了し得る | 予約した通話だけを対象に、2時間の経過タイマーで終了する。端末の時刻変更で制限を外さず、新しい通話へ古い期限を適用しない |
| 古いマイク拒否が新しい通話へ表示される | マイク許可待ちの通話を終え、別の通話に移った後で以前の許可要求が拒否される | 終了済みの通話の失敗結果を無視する。終了後にマイクが許可された場合は、そのトラックを停止する既存動作を維持 |
| 音声活動検出の初期化失敗で音声処理資源が残る | AudioContextを作った後、検出器の初期化で例外になるとコンテキストを閉じない | 失敗時にも閉じ、通常の終了時と共通化する。終了処理の失敗も未処理のPromise拒否にしない。任意の検出器が使えなくてもマイク自体は継続できる |
