| 項目 | 原因・変更 | 確認 |

## 追加調査で再現した問題

| 問題 | 修正・回帰検証 |
|---|---|
| リクエスト本文の到着待ちにログアウト・制限が起きても、古い認証状態で操作が成立する | 本文読込後と署名・セキュア通信の検証後に認証を再確認し、最新のチャット制限・VIP状態等を反映。MFA登録・解除、運営のパスワード再設定、開発者コードも非同期検証後に再確認。送金の引き落としや投稿、MFA登録が残らないことを検証 |
| 同時の活動報告で同じ1分を重複計上する | トランザクション内の最新時刻から計算。12件同時の報告で720秒と数えていたものを約60秒へ |
| 通貨の加算・交換が安全な整数の範囲を超え、以後アカウントデータを読めなくする | 両ランタイム共通のDBトリガーで整数範囲を保護し、APIは409を返す。交換・無料受取・送金受取のロールバック、未受取状態の維持、上限ちょうどでの再受取を検証 |
| 小数のページ件数で500、負数では全件取得になり得る | 日記・運営チャット・運営ログ・観戦ログ・石碑の書き出しに共通の件数検証。通常の件数上限・既定値・運営ログの集計表示は維持 |
| 開発者コードの同時試行が失敗回数を上書きし、同時の初回設定も最後の値で上書きする | ハッシュ検証後に最新の制限回数を参照。保存時は検証したコードが変わっていないことを確認し、競合時は409。12件同時の誤入力で5件を記録して残りを制限し、同時登録は1件だけ成立 |
| 以前のログインのライブ接続・チケット応答が新しい接続を上書きしたり、閉じた接続が遅延イベントを渡す | 接続世代を照合。破棄したチケット取得は次の接続を待たせず、古いWebSocket・SSEの受信と切断通知を無視 |
| IndexedDBの復元完了がログアウトを取り消してしまう | 明示したログイン操作を優先し、古い起動時復元を無視。認証の保存を順序付け、DB接続も処理終了時に閉じる |
| 別アカウントへ切り替えた後の古い成功応答・BAN応答が画面やキャッシュへ適用される | ゲーム・運営・security HOMEで発行元の認証状態を照合。旧プロフィールをキャッシュへ戻さず、別アカウントをBAN画面へ移さない。運営は旧ログインの200応答も実ブラウザで拒否を検証 |
| 初回セキュア通信が同時に来ると異なるサーバー識別鍵を返す | 初期化の進行中処理を共有し、別インスタンスも永続化で勝った鍵を採用。12件同時および8インスタンスの同時開始、再起動後の一致を検証 |
| ログイン画面の遅延フォーカスが、入力中のパスワード欄から名前欄へ戻してしまう | 運営サイト・security HOMEで、既にフォームを操作している場合は初期フォーカスを移さない。ログイン画面が閉じた後も移さない。初期タイマーを入力後まで遅らせる実ブラウザ検査を追加し、異常JSONの通信エラー表示と再操作も維持 |
