# 報酬・VIP給与・権限変更・ログインボーナスの追加監査（2026-10-29）

基点は PR #60 を取り込んだ main `6ef697293aaa1828ee7c25346963baf926f632e8`。使い捨てDBで保存エラー、受付記録の失敗、暗号処理中の対象変更、ログアウト後の遅延応答を発生させて調べた。本番の所持金やアカウントは検査用に変更していない。

## 修正した13項目

| 問題 | 影響 | 修正 |
|---|---|---|
| VIP1週間券使用時の給与境界 | VIP開始前・失効後の未受取給与まで新しいVIP期間の倍率で計算された | 券の消費・期限の更新と同じトランザクションで、以前の条件の給与を先に確定。残高上限なら券・期限・給与起点をすべて保持 |
| VIP EXPによる給与倍率の変更 | スピン・車購入などでレベルが上がると、過去の労働時間まで新倍率になった | 倍率が変わる時に旧条件で給与を確定し、給与クエストと残高通知も反映 |
| アクセス日数の記念報酬 | 送金カード保存が失敗すると、支払済み日数だけ進んで再配布されなかった | 日数の更新・お祝い・送金カードを一括確定 |
| 通報提出時のお礼 | 報酬保存が失敗しても通報が残り、再試行で重複や件数制限を招いた | 通報・報酬・監査ログを一括確定 |
| 通報受理時の報酬 | 処理済み状態だけ残る、または報酬の後のお礼保存で失敗して再試行できなかった | 受理／却下・報酬・お礼・監査ログを一括確定 |
| 意見採用時の報酬 | 採用日時だけ保存されて報酬を再送できなかった | 採用・報酬・お礼・監査ログを一括確定 |
| 登録人数の記念配布 | 一部プレイヤーへの保存失敗でも全体の配布済み印が残った。登録処理の応答も失敗した | 各記念配布を全員分まとめて確定し、失敗分は定期処理で再試行。登録の成功応答は独立して返す |
| 新規登録の監査ログ保存失敗 | アカウントとセッションが作成済みなのに、ログイン情報を返さずエラーになった | 登録・セッション・監査ログを同じトランザクションで確定し、失敗時は同じ名前で登録し直せる |
| 初回の一斉お知らせ | 一部の保存失敗でも送信済み印とメモリ上の完了状態が残った | お知らせ全体の確定後に完了とし、失敗時は次の要求で再試行 |
| 未確定のライブ通知・プッシュ | スピン／ガチャの受付記録保存に失敗して残高が戻っても、結果や残高を先に通知していた | 最も外側のDB確定後に通知・切断処理を実行。ロールバック時は破棄 |
| 未確定の監査ログの外部コピー | DBから戻されたログが外部アンカー・ミラー・通知へ残る可能性があった | 正常に挿入した行の外部反映をDB確定後に統一。挿入自体に失敗した試行の記録は従来どおり保持 |
| 権限付与対象の確認漏れ | コード検証待ちの間に削除・改名・運営昇格された対象へ古い条件で権限を書き込めた。削除済みアカウントへの運営付与も可能だった | 検証後に同じIDの現状・名前・役割を再確認し、対象変更時は拒否 |
| ログインボーナスの非同期処理 | 前アカウントの画面・演出・応答・翌日タイマーがログアウト後も残り、表示復活や状態上書きを起こした。復帰イベントで要求も重複した | ログイン／ログアウト時に一括解除し、世代照合で旧コールバックを無効化。確認要求は同時に1件だけ実行 |

共通のトランザクション処理は、両ホストの「入れ子は外側へ合流する」動作を維持する。内側の例外を呼出元が捕捉しても、一部の書込みだけが確定しないよう外側をロールバックする。確定後の通知失敗は、確定済みの送金やスピンをサーバーエラーに変えない。
