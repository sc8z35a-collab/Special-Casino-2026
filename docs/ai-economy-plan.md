## 0. 目的と前提

### 0.1 目的

1. 両国の人が、月の予算を思い切って上げ、企業の製品をもっと買って経済を回す。
2. 性格による5つの消費傾向（ストレス買い・代償消費・パニック消費・無気力消費・ご褒美消費）を強く出す。
3. ヴェルノアの人は「自分たち一人一人の消費で経済がよくなる」という価値観を持つ。
4. 人口をアスカ15万→**5万人**、ヴェルノア5万→**4万人**に減らす（経済の縮小と雇用の変化は受け入れる）。
5. 9万人全員の頭を大きく強化し、地位と富の上位**300人**（選ばれし300人）はさらに深くして、Cloudflare Workers AIを持たせる。運営サイトで300人の行動をリアルタイムに追えるようにする。
6. Cloudflareの料金は、今の料金に**月¥1,300まで**上乗せしてよい。その範囲で最大まで強化する。

## 1. 人口の再編とアスカの部屋

### 1.1 移住する人を選ぶ

- 世帯ごとに国外へ移住させる。社長・役員・区長・組合の代表・300人の候補は残し、年齢と区の形を保つ。
- 作業は国が休んでいる平日の2:00〜4:00（日本時間、仮）に行い、その間は1分ごとの計算を止める。

### 1.2 財産の分け方（端数を出さない）

世帯ごと移住するので、今の相続（`npc-state.js` の `die`。相続人は世帯の家族だけ）では相続人がほぼいない。そこで移住する人の財産を国ごとにまとめ、残る人へ分ける。アスカの人には株と車がないので、現金だけを扱う。

| 財産 | 分け方 |
| --- | --- |
| トークン・借金 | トークンは現金に戻す。借金はその人の財産から返し、足りない分は銀行の損（`die` と同じ手続き） |
| 現金 | 残る人へ資産に比例して1ドル単位で分ける。切り捨てで余った分は、いちばんお金持ちの人へ |
| 上場株 | 会社ごとにまとめ、その株をすでに持っている人へ持ち株に比例して**1株単位**で分ける。余りの株は端数の大きい人から1株ずつ配る（最大剰余法）。持っている人がいなければ、いちばんお金持ちの人へ。取得単価も引き継ぐ（加重平均）。市場では売らない（株価が崩れるため） |
| 非上場の持ち分 | 1件まるごと1人へ（今の `die` と同じ） |
| 車 | 1台まるごと。カーオーナーが自分の現金（手元資金の2割まで、仮）で下取りし、中古車の在庫にする。そのお金は現金と同じく分ける。枠を超えた分の車は持ち主が持って出る（車はお金ではないので台帳はずれない） |
| 年金 | 納めた分は積立金に残る |

台帳には「人口再編」の行を1回だけ記録し、ずれ$0を確かめる。

### 1.3 番号の付け替えと、空いたスロットの処理

人を詰め直すと番号が変わるので、「古い番号→新しい番号」の表を作り、番号を指している所を一度に直す。**移住した人を指していた所は、必ず空きにする**（存在しない人を指したままにしない）。

| 番号を指している所 | 移住した人を指していたとき |
| --- | --- |
| **人間関係**（`rel`・`close`・`rtrust`） | **そのスロットを空ける**：相手を `-1`、親密度と信頼を `0`。今のコードは `rel < 0` を空きとして飛ばすので、参照エラーにならない。空いたスロットは、その後の会話や出会いで新しい人が入る |
| 世帯のつながり（`hh`・`hnext`） | 世帯ごと移住するので空きは出ないが、残る人の番号は必ず付け替える（V1.3で追加） |
| 配偶者（`spouse`） | `-1` |
| 同居の相手（`host`） | `-1`。居候だった人は、次の日の暮らしの判断（賃貸・実家・居候先さがし）に回す |
| 社長・役員・部署長・課長・名前のある役 | 役職者は移住させない。それでも残った参照は空席にし、今の欠員の手続き（補充・補欠選挙）に回す |
| 組合の代表・区長・署名のリーダー | 同上 |
| 社員名簿・地元企業（`firm`） | 名簿から外す（欠員は採用の対象になる） |
| 非上場の持ち分・株の注文 | 持ち分は1.2のとおり。注文は取り消す |
| いちばんお金持ちの人（`W.richest`）・待っている会話とAIの仕事 | 選び直す・捨てる |
| 地元の商売の持ち主（`W.owners`）・非上場の持ち主（`W.priv`）・市場の取得単価（`cost`） | 付け替える。`W.owners` は作り直す（V1.3で追加） |
| 会社の役職（`W.orgs` の社長・役員・部署・名前のある役）・新事業の担当と社員 | 付け替える（V1.3で追加） |
| 区長・候補・署名・組合の代表（`W.lab`・`W.politics` の中） | 付け替える（V1.3で追加） |
| 会話・理由・出来事の記録（`convos`・`talkFeed`・`reasons`・`events`） | 移住した人の分は捨て、残る人の分は付け替える（V1.3で追加） |

**変わらない番号を足す（V1.3）**：今の人の番号（`pid`＝番号×65536＋世代）は、詰め直すと変わる。データベースに残っている理由の記録や運営サイトのリンクが、別の人を指さないように、詰め直しても変わらない番号の列（`uid`）を足し、記録と画面はこの番号で人を指す。

考え方は、亡くなった人の参照を消す今の処理（`npc-state.js` の `forget`）と同じ。ただし1人ずつ呼ぶと「移住者11万人×全員の人間関係」で重すぎる。そこで移住者に印を付け、全員の人間関係と参照を**1回だけ**見直して、空きにするのと新しい番号への付け替えを同時に行う。`forget` は人間関係の相手だけを `-1` にしているが、ここでは親密度と信頼も `0` にする。

テストで次の2つを確かめる。

- 付け替えたあと、すべての参照が「空き（`-1`）」か「範囲内の、残っている人」を指している。
- 移住した人を指していた人間関係が1つも残っていない。

### 1.4 会社

- ヴェルノアの採用目標を約0.8倍にする（自然減と希望退職）。
- アスカの職を3分の1にする（仮）：ATSUKA Visionは**6万から2万**、地元の商売は**4.5万から1.5万**（V1.3で数字を直した。今の `js/game/asuka.js` は ATSUKA Vision 60,000・地元の商売 45,000）。
- 国の大きさの数字（`W.scale`、アスカの `scale`）は、支店の売上の上限・人数・地代、VIPの人数、車の最初の仕入れなどに使われている。人口を減らすときに変えるかどうかを決める（10章の6）。
- 支店の人員は、各社が今の採算の判断で決め直す。

### 1.5 アスカの部屋の切り出し（減らしたあとの5万人だけを運ぶ）

- `wrangler.jsonc` の `migrations` に、新しい部屋の種類の `v2` の行を足す（`v1` の行には決して触れない）。
- 手順：止める → アスカの状態を写して新しい部屋に書く → 両方でお金の合計が同じか確かめる → 切り替える。
- 元の部屋のアスカのデータは7日間残し、問題があればすぐ戻せるようにする。

## 2. 消費の強化

### 2.1 月の予算

`budgetOf` を引き上げる（仮）：収入から使う割合を60〜98%から**75〜115%**に、資産の取り崩しを**約2倍**にする。

> V1.3：予算を上げるだけでは、企業の製品はあまり買われないことが実験でわかった（11.2の①）。先に「1回に買う額と回数を、その人の残りの予算で決める」直しを入れ、そのあとで引き上げの幅を決める。

### 2.2 5つの消費傾向

1人1人が5つの傾向の強さ（性格から決め、少しばらつかせる）を持ち、そのときの状態で起きる。強さの数字は仮。

| 傾向 | 引き金 | 買うもの | 強さ |
| --- | --- | --- | --- |
| ストレス買い | ストレス・怒り | 雑貨・カー用品・ゲーム課金。買うと万能感が出て、ストレスが下がる | 1回で、1日に自由に使えるお金の2〜3倍 |
| 代償消費 | 自己肯定感が下がる（失業・落選・大損・昇進を逃す） | ブランド品（メゾン・ド・リュクス）・MY WAYグッズ・高級車・VIP | 月の予算を最大+100% |
| パニック消費 | 値上げ・ストライキ・銀行不安のニュースやうわさ | 必需品（フレッシュ・マート・グリーン・フーズ・ジンクス） | 2〜4週間分を買い溜め。品薄と値上がりのあと、反動で買わない |
| 無気力消費 | 疲れ・落ち込みが続く | サブスク・課金・コンビニ（駅ナカの小型店・弁当） | 毎月の固定の出費が増え、なかなか解約しない |
| ご褒美消費 | 給料日・賞与・昇進・大勝ち | 外食・ホテル・ミュージアム・旅行 | 予算を30〜150%超える。くり返すほど慣れて大きくなる |

- 払えないとき：手持ち → 信販（テネシス・オート＆ライフ信販）の分割払い → クイックローン → 買えない。ここで新しいお金は生まれない。
- 後悔して学ぶ人もいれば、「ストレス→買う→借金→ストレス」の悪循環に入る人もいる。

### 2.3 消費観（ヴェルノアの価値観）

- 新しい項目「消費観」。ヴェルノアの人は高く（仮：0.65〜0.95）、アスカの人は**中くらい〜ヴェルノアと同程度**（決定。仮：0.5〜0.85。1人1人をこの間でばらつかせ、平均はヴェルノアより少し低い）。
- 不景気のときや地元企業が苦しいときに「応援消費」をする。会話・街の声・区長の公約（消費応援）で広がる。
- お金に余裕のない人は控えめにする。
- アスカには自分の国の会社がないので、アスカの人の応援消費は、地元の商売・アスカ・リゾート・アスカの人が働く支店に向かう。
- アスカでは支店が足りず、今でも買いたい分の7〜9割が買えていない（11.2の②）。消費観を上げても企業に届くように、支店の増やし方の直しと一緒に入れる。

### 2.4 歯止め

- 今の物価と金利の仕組み（`npc-macro.js`・テネシスの金利決定）に任せる。銀行は自分のお金しか貸さない。
- シミュレーションの目標：インフレ率が年0〜6%、失業率が2〜6%、台帳のずれ$0。

## 4. 選ばれし300人

### 4.1 選び方と頭

- 地位（45社の社長・役員、区長、組合の代表、ATSUKA Visionの幹部）と富の上位から選ぶ。月に1回見直し、入れ替わりの境目に余裕を持たせる。亡くなった人の枠は補充する。
- 思い出2,500件・人間関係300人・目標の木・親しい人の「心のモデル」。大きな判断は1,024通りの先読みで決め、強欲などの感情の偏りを混ぜる。
- 深い考えは各部屋で1分に30人ずつ順番に行う（プレイヤーの操作を待たせないため）。
- メモリに置くのは1人約30KB。日記30日分はデータベースに置く。

### 4.2 Workers AI

- 10人分を1回で聞き、答えは記号で受け取る（例：「投資・RIRU・3」）。エンジンが選べる行動かを確かめてから実行する。
- モデルはP0で比べて決める（仮：granite-4.0-h-micro）。1回の入力を約1,200トークン・出力を約300トークンとした見込み：

  | モデル | 1回のNeurons | 300人を回せる間隔（平日11〜22時） |
  | --- | ---: | ---: |
  | granite-4.0-h-micro | 約4.9 | 約3.5分に1回 |
  | llama-3.2-3b | 約14.7 | 約13分に1回 |

- 定時の間隔は5分ごとを目標にする。
- **優先起動**：資産の急変・大負け・失業・落選・大きなニュースで呼ぶ。1人30分に1回まで、その日のAI予算の25%まで。
- **満員にしてから呼ぶ**：1分待っても10人に満たないときは、次の定時に呼ぶ予定だった人を前倒しして10人にする。
  - 前倒しした人は次の定時を数え直し、二重には呼ばない。
  - 前倒しできる人がいなければ少ない人数のまま呼び、急ぎの人を1分より長く待たせない。
  - 同じ部屋の人どうしでだけまとめる（前置きにその国の様子が入るため）。
  - 満員にすると、1人あたり約0.67から約0.49 Neuronsになる（granite）。
- **予算は2部屋で1つ**：本体がその日のNeuronsを管理し、アスカの部屋へは1分ごとのやり取りで配分を渡す（はじめは3分の1）。使わなかった分は本体へ戻す。
- 心の声と日記の文は1人1日数件。区長の演説は今の gemma のまま。

  - 開いている間だけWebSocketで購読する（70秒ごとに更新）。サーバーは1分ごとに変わった所だけを送り（約5KB）、行動に付けた秒の時刻どおりに画面が表示する。定期的な問い合わせはしない。
- **保存**：
  - 保存と読み込みを、列ごと・1MBずつ書く形に直す（一時的なメモリの増加を数MBに抑える）。
  - 300人の直近4時間の行動は、今の5分ごとの保存に相乗りする。
  - 日記は1人1日1行で、30日分を古い順に上書きする（月約9,000行）。

### 11.1 計画どおりで正しかったこと

| 項目 | 確かめた結果 |
| --- | --- |
| 0.3の大きさと速さ | ヴェルノア1人499バイト（計23.8MB）、アスカ1人62バイト（計8.9MB）。1分の計算は平均4.6ms・最大76ms、1日の締めは0.3〜0.46秒。計画書の数字と合う |
| 予算の式 | `budgetOf` は収入の60〜98%と資産の年1.5〜6.5%（倹約な人ほど資産の分が下がり、最も倹約な人はその半分） |

| `forget` | 人間関係の相手だけを `-1` にしている（親密度と信頼は残る）。1.3で `0` にするのは正しい |

### 11.2 このままだと狙いどおりにならない所

#### ① 予算を上げても、企業の製品はあまり買われない

8,000人の国で20日間、全員の月の予算（とその中の4つの財布）を1倍・2倍にして比べた。

| 20日間の売上 | 1倍 | 2倍 | 増え方 |
| --- | ---: | ---: | ---: |
| Dtrade（スロット） | $0.19B | $0.41B | +116% |
| ジンクス | $0.87B | $1.43B | +64% |
| ICE（ゲーム） | $0.28B | $0.32B | +14% |
| DAIZIN・Car Owner・MY WAY・RIRU・MAGITA | | | ほぼ0% |
| 人が使ったお金の合計 | $2.66B | $3.73B | +40% |

- 予算はスロット・ゲーム・レジャー・投資の4つの財布にしか入らない（毎日の暮らしの買い物は別の式）。
- 1回の買い物の額は国の平均（`W.cal.leisure`・`W.cal.lounge`）で上限が決まり、その人の予算では決まらない。車・VIP・MY WAYのグッズは決まった確率と資産で決まり、予算を見ていない。
- 今でも予算は使い切られていない：レジャーの財布は約47%、ゲームの財布は約10%しか使われない。
- **直し方**：2.1の前に、「1回に買う額」と「買いに行く回数」を、その人の残りの予算（心の財布、11.3の3）で決まるようにする。高い物（車・VIP・ブランド・旅行）も予算と気持ちで決まるようにする。月末に残った予算は「貯める・来月へ回す・使い切る」を性格で選ぶ。

#### ② アスカでは、買いたい分の7〜9割が買えていない

5,000人（アスカ1.5万人）の国で60日間。

| 日 | 買うつもりの額（1日） | 実際に買えた額 | 買えた割合（車・日用品） |
| --- | ---: | ---: | ---: |
| 10日目 | $72M | $6M | 0%・0% |
| 30日目 | $73M | $12M | 4%・1% |
| 60日目 | $74M | $22M | 9%・2% |

- 支店が足りない。支店は月に最大25%（はじめは1か所ずつ）しか増えず、買えなかった分はそのまま手元に残る。
- このままアスカの消費観を上げても、お金は企業に届かない。
- **直し方**：支店を「足りない分」に合わせて速く増やす（例：足りない分の3分の1を毎月）。買えなかった分の一部は地元の商売やアスカ・リゾートで使う（代わりに買う）。「品切れで買えなかった」を不満として残し、うわさにする。

#### ③ 気持ちと思い出の多くが、判断に使われていない

| 持っているもの | 判断に使われているか |
| --- | --- |
| 気分 | 使われている（スロット・予算） |
| ストレス・怒り | 増えたり減ったりするが、どの判断にも使われていない |
| 不安 | どこにも使われていない |
| 幸福 | 気分の戻る先としてだけ |
| 思い出16件 | 「大負け」をスロットの判断に使う1か所だけ |

- 思い出を96件に増やしても、読まれなければ賢くならず、メモリだけが増える。
- **直し方**：「増やす前につなぐ」。今ある気持ちと思い出を、5つの消費傾向・仕事・お金の判断につなぐのを先にする。

#### ④ 2部屋にしても、128MBを分け合うおそれがある

- Cloudflareの説明では、メモリの上限128MBは「アイソレート（プログラムが動く箱）」ごとで、1つの箱に複数のDurable Objectが入ることがある。
- 本体66〜76MB＋アスカ58MB＝124〜134MB。同じ箱に入ると上限を超える。
- **直し方**：アスカの部屋のクラスを**別のWorker**に置き、`script_name` で結ぶ（別のWorkerどうしは同じ箱を使わない。P0で確かめる）。それができなければ、2部屋の合計を100MB以内にする。

#### ⑤ 細かい点

- 保存の `meta`（1行のJSON）は2日で0.5MB（市場の注文が422KB）。300人の思い出・日記・心のモデルは `meta` に入れず、列の形で分けて保存する（1行2MBの上限）。
- 一般市民も、サーバーが空いているときは1,024〜4,096通りの先読みをしている（`npc.js` の `tune`）。300人の「1,024通り」は一般市民と同じ深さなので、数でなく中身で差をつける（11.3の6）。
- 今のAIの使用量は `npc_ai` の表で数え、1日9,000 Neuronsで止まる。300人のAIを同じ表・同じ上限で数えると、そこで止まる。メーターを分ける。
- 国の計算は「同じ鍵なら同じ結果」になるように作られているが、AIの答えは毎回違い、届くのも遅れる。AIの答えは「入力」として記録し、次の1分にエンジンが確かめてから使う。テストでは記録した答えを流して、同じ結果になるのを確かめる。
- 富の偏り：上位2%が全員の予算の39%を持つ（予算の中央値は約$36万、平均は約$79万）。資産の取り崩しを2倍にすると、増えた分の多くはお金持ちの消費になる。ふつうの人の消費を増やすには、収入の側（給料日・賞与・心の財布）を強くする方が効く。

### 11.3 この案をこえる賢さの案（提案）

1. **頭を3段にする**（反射・1日の予定・熟考）
   - 反射：今の「1分ごとの選択」（そのまま。速い）。
   - 1日の予定：朝に「今日すること」を1つか2つ決める（給料日だから外食、週末に車を見に行く）。1分ごとの選択はこの予定に引っぱられる。
   - 熟考：大きな判断（車・転職・借金・投資）は今の先読み。
   - 300人のAIは「目標と予定を決める係」にし、1分ごとの行動はエンジンが行う。AIが1回で決めたことが数時間〜数日続くので、少ない回数で賢く見える。
2. **1人1人が「世の中の見通し」を持つ**（信念）
   - 「値上がりしそうか」「自分の会社は危ないか」「株は上がりそうか」の3つ（各1バイト）。
   - ニュース（`aware`）・会話・自分の体験で少しずつ変わる。信じやすさは性格（`news`・`learn`）で違う。
   - パニック消費（値上がりを信じた人が買い溜め）や応援消費（地元が苦しいと聞いた人）、うわさの広がりが、決めたルールでなく見通しから自然に起きる。
   - 先読み（`ahead`）も、国全体の見通しでなく、その人の見通しで行う。
3. **心の財布と「慣れ」**
   - お金を出どころで分けて覚える：給料・賞与・大勝ち・貯金。賞与や大勝ちのお金は気軽に使い（ご褒美消費）、貯金は倹約な人ほど守る。
   - 「いつもの暮らしの水準」を持つ。ご褒美をくり返すと水準が上がり、収入が下がっても水準はなかなか下がらない。これで「ストレス→買う→借金」の悪循環が自然に起きる。
   - 5つの消費傾向は、別々のルールでなく「気持ち×見通し×財布×水準」の組み合わせから起きるようにする。調整が楽で、組み合わせの行動（落ち込み＋賞与＝大きな代償消費）も生まれる。
4. **思い出は「数」より「教訓」**
   - 毎晩、その日の思い出から「教訓」（8〜16個、各1バイト）を更新する（スロットは損をする・この会社は信用できる・車を買ってよかった・借金はこわい）。
   - 判断は教訓を見る。思い出そのものは32件ほどで足りる（96件より軽く、賢い）。
   - 300人は日記と教訓をAIに渡し、「自分はどういう人か」を言葉にしてもらう（AIの振り返り）。
5. **周りを見て買う**（流行と見栄）
   - 親しい人が新しい車・VIP・ブランドを買うと、見栄の欲求が上がる（代償消費・見栄の消費）。
   - 製品の評判（買った人の満足）が会話で広がり、流行や「これは失敗作」が生まれる。
   - 買ったあとの満足と後悔を製品ごとに学ぶ（ブランドの好みが体験から育つ）。
6. **選ばれし300人を中身で賢くする**
   - 先読みを、その人の会社の決算・金利・物価の見通しにつなげ、悪いことがまとめて来る形（景気の波）で未来を引く。
   - 選択肢を「買う・買わない」から「いくら・いつ（今か、セールまで待つか）」に広げる。
   - 心のモデル：親しい人・取引相手・会議の相手が「どう動くか」を予想し、会議での発言や交渉に使う。
   - AIは個人の買い物より、会社の会議（予算・値段・採用・新事業）での発言に使うと、国全体への効きが大きい。エンジンが変えてよい幅を決め、その中だけ動かす。
7. **AIを安く、よく使う**
   - 答えは記号だけにし、出力を1回300→150トークンほどに減らす（出力は入力の約6.6倍高いので、1回約4.9→約3.4 Neurons、約3割安い）。浮いた分で間隔を短くするか、渡す情報を増やす。
   - 答えの形（JSON）を決めて、読めない答えを減らす。
   - **影の比べ**：はじめの数週間は、AIの案とエンジンの案を両方出し、実行はエンジンにする。結果（資産・満足・失敗の数）を比べ、AIの方が良い所だけAIに任せる。
8. **賢さを測るテスト**（シナリオテスト）
   - 値上げで買う量が減るか、セールで増えるか。
   - 大負けのあとスロットを控えるか（控えない人もいるか）。
   - 給料日に外食が増えるか。パニック消費が起きて、そのあと落ち着くか。
   - 払えない物を借金して買い続ける人がいるか。その人の一部が懲りるか。
   - これをP2〜P4の終わりの目安にする。

1人の大きさの見込み：見通し3・教訓16・心の財布と水準約40・予定と目標約20・5つの傾向と消費観6・家計簿（直近20回を2バイトずつ）約40・思い出を32件に（+64）で、**約+190バイト（1人約690バイト）**。人間関係を24人にするなら +72バイト。1KBより軽く、2部屋の合計に余裕ができる。
