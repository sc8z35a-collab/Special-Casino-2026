# DOMへのデータ表示

**ユーザー入力・他人のデータは textContent で表示する。innerHTML に入れない。**

名前・メッセージ・運営コメント・サーバーや外部から受け取ったデータは、
`js/ui/kit.js` の `el(tag, cls, text)` または要素の `textContent` で表示します。
改行や装飾が必要なら、要素を作って `appendChild` で組み立てます。

`node tools/check_inner_html.cjs --self-test` は `js/` と `ops/` のJavaScript・
TypeScript・HTML・SVGソースを再帰的に調べます。生成バンドルやvendorも除外しません。
push / pull_request のテストCIでも必ず実行します。外部依存パッケージは不要です。

| 既存の許可箇所 | 件数 | 許可の理由 |
| --- | ---: | --- |
| `js/render/fx.js` のsun・beam・titleコンテナ | 3 | 空文字でクリア |
| `js/main.js` のreelFrameフォールバック | 1 | 自前の静的SVG生成 |
| `js/main.js` のWIN枠 | 2 | 静的な固定HTML。金額は別途textContent |
| `js/ui/screens.js` の配当表 | 1 | 自前の画像と数値ルール |
| `js/ui/feedback.js` のOFFER_SVG | 1 | 自前の静的SVG定数 |

許可リストはスクリプトの `ALLOWED` に8箇所のコード断片として明示しています。
ファイル単位の許可や件数だけの比較ではありません。既存の断片の変更・削除・複製や、
許可箇所以外での追加は失敗します。行番号の移動は許容します。
既存8箇所のアプリケーションコード自体は変更していません。

このチェックは事故を防ぐ保守用の保守的な文字列検査で、完全なXSS解析器ではありません。
角括弧構文も検出しますが、動的に組み立てたプロパティ名などのデータフローは解析しません。
ソース内のコメントや文字列にある同名の単語も検出します。
例外の式が参照する定数や関数にユーザー入力が流れ込まないことも、レビュー時に確認してください。
失敗時はまずtextContentでの実装へ戻し、許可リストを機械的に増やして通さないでください。
