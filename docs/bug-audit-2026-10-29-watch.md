# 観戦・通話の遅延応答と車の出品の追加監査（2026-10-29）

基点は PR #59 を取り込んだ main `5cebed1f399e79373c413dc849ffb42ada7f99cf`。前回までの修正を維持し、通信の応答順が入れ替わる場合、初めて観戦される場合、ログアウトやアカウント削除をまたぐ場合を調べた。本番アカウント・本番の車や所持金は操作せず、使い捨て環境で再現している。

## 修正した11項目

| 問題 | 再現した影響 | 修正 |
|---|---|---|
| 初めて観戦された側の操作UIが出ない | 観戦UIを自分が観戦する時だけ遅延ロードしていたため、一度も観戦したことのないホストでは観戦者表示や通話相手の選択が使えなかった | 最初の被観戦通知、または観戦者のいる再接続通知で必要なUIを一度だけロードし、現在の参加者を取得する。起動時の一括読込みは復活させない |
| 遅い観戦開始応答が終了操作を取り消す | 読込み中の終了、別画面の選択、自分のスピン開始、フレンド解除の後でも、古い応答で観戦画面を開いた | 操作・ナビゲーション・アカウントの世代を照合。無効な応答は画面へ適用せず、不要になったサーバーの参加も解放する |
| 観戦相手の切替と古い終了要求が競合 | 相手A、Bの応答順が逆になると古いAが表示された。Aへの古い終了要求だけでも、サーバー上のBへの参加まで削除された | 観戦の制御要求を順番に処理し、サーバーの終了操作も指定した相手への参加だけを削除する |
| 古い再接続の失敗が新しい観戦を閉じる | Aへの再接続を待つ間にBへ切り替えても、Aの失敗通知がBを終了した | 再接続の成功・失敗を、開始時の操作と現在の相手に結び付ける |
| 古い参加者一覧が退出者・音声許可を復活させる | 再接続の一覧が逆順に届いたり、その取得中に参加者が退出すると、古い一覧から消した相手が戻った。取得中の音声許可・解除も上書きされた | 最新の一覧要求だけを採用し、取得中の参加・退出・音声変更を優先して統合する。変更のない参加者は一覧から補完する |
| 遅い通話許可応答で終了後にマイクが起動 | ホストの許可操作を待つ間に通話を終了したり相手が退出しても、古い成功応答がマイク起動を実行した | 最新の操作、現在のアカウント、同じ参加者オブジェクトを確認してからマイクを起動。退出した別の相手も古い音声一覧から戻さない |
| 許可の確定前に通話を終了すると後から再開 | まだ許可が確定していない相手は終了要求の対象に入らず、遅い許可イベントで通話が再開した。ハブから古いホームへ戻る経路も残った | 要求中の許可も撤回対象に含め、制御要求の順番を保つ。終了直後はローカルでも通話を抑止し、復帰先の情報も更新する |
| 退出前の許可が同じ相手の再参加へ適用される | 許可要求の本文受信を遅らせ、相手を退出・再参加させると、古い要求が新しい参加に音声を許可した | 既存の参加日時を単調な識別情報として返し、現在の参加と照合して不一致を409で拒否。同じ参加への再送では識別情報を維持する |
| 明示的な観戦終了でも再接続用の音声同意が残る | 接続断で保存された同意は、ユーザーが観戦を終了しても消えず、再度入ると音声が復元された | 指定した相手からの退出時に、その相手の再接続用同意も破棄する。単なる接続断からの通常復旧は維持する |
| ログアウト後に以前のホーム情報が残る | 自分が観戦中でなければ終了処理が何もせず、前のアカウントの観戦者表示が残った。古い一覧や開始応答も次のログインへ適用できた | ログアウト用のリセットで参加者・チャット・保留操作を消す。古い要求を無効化し、新しいアカウントの操作は古い要求の完了を待たせない |
| 削除済み購入相手への出品が車をロック | 購入相手の本削除で販売メッセージは取消済みになるが、車の出品IDが残った。取消操作も「取消済み」で拒否され、売却・贈与・再出品ができなかった | 本削除時に車の出品IDも解放。既に残っている取消済み・参照切れのロックも、ガレージ表示や車の操作時に所有者の車だけを検査して修復する。有効な出品は解除しない |

## 検証

- Node全638テストが成功。追加24テストは、遅延応答、音声許可、アカウント切替、サーバーの参加照合、車の出品解放と通常操作を確認する。
- 基点の隔離したソースで、クライアント17ケース・サーバー3ケースの失敗を再確認。車の本削除と既存ロックも変更前に別々に再現し、合計22ケースの再現条件を確認した。通常の許可や同じ参加への再送も修正後のテストで維持した。
- 実ブラウザで初回の被観戦UIが出ないことを変更前に再現。修正後は必要なスクリプトを1回だけ取得し、観戦者が表示される。
- 新しい必須検査 `tools/check_watch_lifecycle.cjs` は、実ゲーム・実サーバーへの要求を行い、応答の適用だけを意図的に遅延させる。終了後に画面が戻らないこと、UIとサーバーの観戦相手の一致、フレンド解除、通話終了後のマイク起動防止を検査する。
- Chromiumの仮想音声入力を使った実MediaStreamで、遅い許可を取り消した場合はマイク取得0回、通常の許可では1回、終了後は取得した全トラックがendedになることを確認した。物理マイクやスマートフォン実機の検証とは区別する。
- 既存の観戦画質検査、スピン・ガチャ再送／認証／運営権限のブラウザ検査、Python 8テスト、CI登録・配信用minify・SHA固定・テスト分割・更新識別子・README同期が成功。
- API入力検査2,724回で予期しない500は0件。今回の変更で権限・配当・価格の仕様を変えない。
- Node／Workersの共通契約検査に、参加識別情報、古い音声許可の拒否、切替後の古い終了要求を追加。Node側の29契約はローカルで成功。実workerdで同じ29契約が一致すること、R2の復旧、実音声RTP、新しいブラウザ検査を含む必須CIの成功をマージ条件とする。

## 互換性と負荷

- DBの新しい列やテーブルは追加しない。音声操作の参加識別情報は省略可能とし、旧クライアントとの互換を維持する。参加識別情報の照合は、それを送る現行クライアントに適用する。
- 観戦と音声の制御要求だけを順番に処理する。スピンや通常チャットをこの待機列には入れない。追加の常駐ポーリング・定期タイマー・動画・モデルは設けない。
- 初回の被観戦でのみ必要なUIを読み込み、取得中の複数通知もまとめる。車の既存ロックの検査は、その所有者の車に限定する。
- コイン、ガチャの価格・確率、スロットの配当、VIP、報酬、通常の取引は維持する。この監査は、すべての端末やあらゆる通信順序で不具合がないことを保証するものではない。
