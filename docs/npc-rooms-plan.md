## 1. 料金

### 1.1 決まり（Cloudflareの公式の料金表）

- 部屋が起きている間の料金は、使ったメモリではなく**部屋1つにつき128MB**で数えます。40MBしか使わない部屋も128MB分です。
- 毎月の込みの分（40万GB秒）は、部屋ごとではなく**アカウント全体で1つ**です。
- 休める状態の部屋（タイマー・見回り・届いた呼び出しがない部屋）は、料金に数えません。
- 計算の量（CPU）は、別には数えません。起きている時間だけで数えます。だから起きている5時間のうちは、計算をたくさんしても料金は同じです（7.9）。

### 1.2 見積もり（31日の月。込みの分は本体が使い切ると考えた、いちばん高い場合）

| 項目 | 計算 | 月の額 |
| --- | --- | ---: |
| 動いている時間 | 8部屋 × 0.125GB × 18,000秒 × 31日 ＝ 55.8万GB秒 | ¥1,046 |
| リクエスト | 8部屋 ×（見回り9,300回＋本体とのやり取り9,300回）＝ 約15万回 | ¥3 |
| 書き込み | 約22万行（2.4） | ¥34 |
| 保存の容量 | 約2.1GB（6.3） | ¥63（込みの5GBに入れば¥0） |
| **合計** | | **約¥1,146** |

- 余裕は約¥150（12%）です。1ドル＝170円の円安までなら、¥1,300を越えません。
- 本体が込みの分を使い切っていなければ、実際はもっと安くなります。

### 1.4 料金の見張り役（本体に1つ）

- 各部屋が起きた時刻と眠った時刻を本体に知らせます。本体は毎日、今月の見込みを円に直します（為替は設定で変えられる）。
- 見込みが¥1,250を越えたら、その月の残りは終わりの時刻を早めます（21:55、21:50…）。22:00より遅くすることはありません。
- 時間外に起きている部屋を見つけたら、すぐに眠らせてDiscordに知らせます。

## 2. 5時間だけ動くしくみ

### 2.1 一日の流れ

| 時刻 | すること |
| --- | --- |
| 17:00 | 本体の見回りが、8部屋に「開く」を送る。各部屋は保存から全員を読み込む（約82MB・約40行） |
| 17:00〜17:05 | **昼の要約**：前の日の22:00から17:00までの19時間（睡眠・朝・通勤・仕事・昼食・休日の外出）を、1時間刻みで少しずつ計算する。考え方は夕方と同じ頭（7章） |
| 17:05〜21:45 | 1分ごとの生活（今と同じ「次に動く時刻」方式）。仕事帰り・買い物・友達・家族・遊び・投資など |
| 21:45〜21:55 | **夜の振り返り**（7.8） |
| 21:55 | 全員を保存する。公開用の写し（身分証明書・プロフィール）を本体へ送る |
| 22:00 | タイマーと見回りをすべて消し、休める状態にする。料金が止まり、まもなくメモリから消える |

- 会社の日の締め（毎朝9:00、本体）は、前の日の夕方と昼の要約で動いたお金で行います。
- 給料日・家賃・請求は、その日の17:00の昼の要約の中で払います。

### 2.2 5時間を越えないための守り

- 人の部屋のWorkerには、外から入る道を作りません。本体からの呼び出しだけを受けます。
- 本体は、17:00〜22:00以外に人の部屋を呼びません（呼ぶ関数の入口で止める）。運営サイトと街ライブは、時間外は本体にある写しを見ます。
- 人の部屋は、時間外に呼ばれたら何もせずにすぐ返します。
- 起きている間は、1秒ごとの小さなタイマーで眠らないようにします（今の本体と同じ方法）。途中でメモリから消えると、全員の読み直しになるためです。

### 2.3 落ちたとき・起きないとき

- **送り状は先に保存**：部屋は、本体へ送る送り状を、送る前に自分の保存（出口の箱）に書きます。部屋が落ちたら、最後の保存（10分以内）から戻して、出口の箱の送り状を当て直します。こうすれば、本体が受け取った額と必ず合います。本体は送り状の番号で、二重に受け取らないようにします。
- **起きないとき**：本体が1分ごとに5回まで呼び直します。それでも起きない部屋は、その日は休みにします（次の日の昼の要約にまとめて計算）。Discordに知らせます。

### 2.4 保存（書き込みの行数）

| 保存 | 1部屋1日 |
| --- | ---: |
| よく動く分の保存（10分ごと） | 約300行 |
| 全員の保存（21:55） | 約40行 |
| 出口の箱（1分ごと） | 約300行 |
| その日の思い出の束 | 約5行 |
| 倉庫の整理（月1回、1人1行） | 月6,667〜8,000行 |

8部屋で月約22万行です。表には主キーだけを使い、別の索引は作りません（索引の書き込みも行数に数えられるため）。

## 3. 部屋の分け方

- 部屋は全部で9つです。**本体**（今のCasino：プレイヤー・会社・株の市場・両国の国の帳簿・お金の台帳・人の写し）と、**人の部屋8つ**です。
- 人の部屋は、**1つずつ別のWorker**にします（`npc-v1`〜`npc-v3`・`npc-a1`〜`npc-a5`）。
  - 同じWorkerの部屋は、1つの入れ物（isolate）に一緒に入ることがあり、そのときは128MBを分け合ってしまいます。別のWorkerなら必ず別々です。
  - 本体からは、`script_name` を付けた結びつけで呼びます。
  - 本体の `wrangler.jsonc` の `migrations`（`v1`）には触れません。人の部屋の種類は、人の部屋のWorkerの側で作ります。
  - 有料プランのWorkerの上限（500）にも、部屋の種類の上限（500）にも、十分な余裕があります。

| 部屋 | 区 | 人数 |
| --- | --- | ---: |
| npc-v1 | ソレイユ区・アイゼン区（約3,333人ずつ） | 約6,667 |
| npc-v2 | カナリア区・オーロラ区（約3,333人ずつ） | 約6,667 |
| npc-v3 | リヴィエール区（川沿いの住宅地。人口はほかの区の2倍） | 約6,667 |
| npc-a1〜a5 | ハルカ区・ミナト区・フリーコマースゾーン・アカツキ区・ソラ区（1部屋1区） | 8,000ずつ |

- 世帯は必ず同じ部屋にします。部屋をまたぐ引っ越しは、その人のデータを丸ごと、次の夕方に本体を通して移します。
- 9部屋以上にしない理由：料金の余裕が2%以下になります（1.3）。また、部屋が増えるほど、部屋をまたぐ友達・同僚・お金のやり取りが増え、ずれや遅れの元になります。

## 4. 部屋どうしのやり取り

- **星形**：人の部屋は、本体とだけ話します。人の部屋どうしの話（友達・同僚・別に住む家族）も本体が仲立ちし、1分遅れで届きます。
- **人の呼び名**：部屋の番号＋番号＋世代（`uid`）。部屋をまたいでも、詰め直しても変わりません。
- **お金**：人のお金は人の部屋に、会社・国・銀行のお金は本体にあります。
  - 1分ごとに、番号付きの送り状でまとめて運びます。
  - 送っている途中のお金も台帳で数えます。
  - 毎日22:00に、全部の部屋と本体を合わせて、ずれ$0を確かめます。
- **国のこと**：選挙・署名・組合・株の市場は本体がまとめます。人の部屋は票や注文を送るだけです。

## 5. メモリ（1部屋128MB）

| 中身 | 大きさ |
| --- | ---: |
| プログラムと実行の環境 | 約12MB |
| 部屋の状態（区・店・国の知らせ・送り状） | 約6MB |
| 作業用（保存の1行2MB・倉庫の読み込み・昼の要約） | 約8MB |
| 人（ヴェルノア6,667人×12KB／アスカ8,000人×10KB） | 約82MB |
| **合計** | **約108MB**（上限まで約20MB） |

- 保存は列ごとに2MBずつ書きます。今のように全員を1つにつなげることはしません（今は保存の瞬間に約39MB増える）。
- メモリの見張り：112MBを越えそうなら、古い思い出を早めに倉庫へ移します。
- P0で、プログラムと実行の環境の大きさを実測して、1人の大きさを決め直します。軽ければ、そのぶん1人を大きくします。
- 本体からは、人のデータ（今は約55MB、保存の瞬間はさらに約39MB）がなくなります。本体のメモリにも大きな余裕ができます。

## 7. 賢くする工夫（AIなし）

### 7.1 選択肢の目録

- 人ができることを全部（約150種類）、コードの中に1回だけ書きます。それぞれに、できる条件・お金・かかる時間・結果・危なさを持たせます。
- 仕事・転職・買い物・車・家・借金・貯金・投資・保険・健康・病院・家族・結婚・引っ越し・遊び・政治・人づきあいまで含めます。
- 人は、何かを決めるたびに、**自分が今選べることを全部並べて**比べます。

### 7.2 選択を理解する

- 全員が、自分の選べることと、その決まり（値段・条件・どうなるか）を全部わかっています。
- わからないのは将来（景気・運・他人の気持ち）だけです。そこは、自分の見通し（6.1）で予想します。
- 見通しの当たり方は、経験・友達の話・ニュース・勉強で、人ごとに上がっていきます。

### 7.3 決め方

- 点数 ＝ 目標・欲求・気持ち・人間関係・健康・将来のお金への効き目の合計 − 危なさ×その人の慎重さ。
- **先読み**：大きな決断（転職・車・家・借金・投資・結婚・引っ越し）は、自分の見通しで1〜12か月先を256通り試してから選びます。
- 5つの消費傾向（V1.3の2.2）と消費観は、気持ちと価値観として、この点数に入ります。

### 7.4 理由を持つ

- 決断ごとに、選んだもの・比べたもの・理由の上位3つ・予想した結果を残します（6.1の「決断と理由」）。
- 結果が出たら答え合わせをします。
- プロフィールで「なぜそうしたか」を文にして見せます。文は `server/core/npc-text.js` の型で作り、AIは使いません。

### 7.5 学ぶ

- 行動ごとの「うまくいった度」を、結果で少しずつ直します。同じ失敗が減り、その人らしい癖が育ちます。
- 予想と結果の差で、見通しを直します。
- 大きな成功や失敗は、教訓として残します。

### 7.6 他人を考える

- 親しい8人の心のモデル（性格・お金・気分・考えていることの推測）を持ちます。
- 相談・まね・うわさ・嫉妬・助け合い・お金の貸し借りに使います。

### 7.7 目標の階層

人生の目標（結婚・家・昇進・独立など）→ 1年の目標 → 月の計画 → 今日の予定、の順に決めます。

### 7.8 夜の振り返り（21:45〜21:55）

- その日の決断の答え合わせをして、学んだこと・見通し・教訓を直します。
- 日記を1行書きます。
- 思い出を整理します。大事なものはメモリに残し、残りは倉庫へ移します。

### 7.9 計算の配分

- 計算の量は料金に数えられないので（1.1）、1分のうち最大20秒を考える時間に使います（1回の制限は30秒。人の部屋のWorkerは `limits.cpu_ms` を60秒にして余裕を持たせる）。
- 8,000人の部屋で、1人1分あたり約2.5ミリ秒になります。
- 全員が毎分軽く考え、約10分に1回は先読みで深く考えます。

### 7.10 昼の要約も同じ頭で

17:00の昼の要約（2.1）も、1時間刻みで同じ決め方を使います。夕方だけ賢く、昼は機械的、ということにはしません。

## 8. 人口とお金の再編

### 8.1 人口

- ヴェルノアは5万→2万（0.4倍）、アスカは15万→4万（約0.267倍）。
- 移住は世帯ごとにします。社長・役員・区長・組合の代表は残します。年齢・区・お金持ちと貧しい人の形を保ちます。
- 規模の数字は、ヴェルノア0.4、アスカ約0.267にします。アスカは自分の規模の数字を持ちます（今のコードは「アスカの人口＝ヴェルノアの3倍」で、規模もヴェルノアのものを使っている）。

### 8.2 お金

- 移住する人は、**自分のお金を持って国を出ます**（V1.3の1.2「残る人へ分ける」はやめる）。
- 国のお金（国庫・年金の積立金・国の銀行・ATSUKA Vision・企業誘致の資金・地元の商売）も、同じ割合で減らします。
- 減らした額は、台帳に「人口再編（国外へ）」として1回だけ記録します。毎日のずれ$0の確認は、そのまま通ります。
- プレイヤーのお金・株・車には触りません。上場企業の現金も減らしません（減らすと株価が下がり、プレイヤーの資産が減るため）。

### 8.3 会社の人数（ルールの数 × 規模）

| | ルールの数 | 実際の人数 |
| --- | ---: | ---: |
| テネシス | 2,000 | 800 |
| MAGITA | 2,800 | 1,120 |
| YOSIDA | 2,000 | 800 |
| ジンクス | 1,000 | 400 |
| カーオーナー | 600 | 240 |
| ほかの9社・テネシスリサーチ・地元企業 | 13,810 | 5,524 |
| **ヴェルノアの合計** | **22,210** | **8,884** |

- ヴェルノアで働ける人は約14,100人（2万人の70.5%）なので、足ります。
- アスカは、ATSUKA Vision 1,500人（最低の数。規模はかけない）＋ほかの会社 約4,950人＋地元の商売 12,000人（人口の30%）＝ 約18,450人です。働ける人は約31,600人（4万人の79%）なので、足ります。
