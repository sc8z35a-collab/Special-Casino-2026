# 課金・認証情報・送金・受取の追加監査（2026-10-29）

基点は PR #61 を取り込んだ main `e52e5c0db627825c9f050208bcd0336dfae7b99e`。保存エラーと通信待ちの間の権限変更を、使い捨てDB・ローカルの模擬決済サーバーで再現した。本番の注文・残高・認証情報は検査用に変更していない。価格、配当、確率、VIP特典、正常時のAPI形式は維持している。

## 修正した11項目

| 問題 | 再現した影響 | 修正 |
|---|---|---|
| 認証情報更新後の監査保存失敗 | 本人・運営によるパスワード変更や引き継ぎコード再発行で、更新後にエラーとなり旧情報や旧セッションだけが無効になった | 認証情報・セッションの更新と監査を一括確定。失敗時は旧状態を保持し、安全に再試行できる |
| 送金後の監査保存失敗 | エラー応答なのに送金元が減額され、送金カードも作成・通知済みになった | 日次上限、残高、カード、クエスト、監査を同じトランザクションへ。通知は確定後のみ |
| 受取後の監査保存失敗 | お金・アイテム・車が移動して受取済みになったのにエラーを返し、再試行できなかった | 資産移動・受取済みの印・監査を一括確定 |
| 課金確定後のお礼／監査保存失敗 | コインと注文だけ確定し、Webhookの再試行でもお礼や監査が残らなかった | 注文の同期を外側のトランザクションでまとめ、コイン・注文・お礼・監査を一括確定 |
| 返金後の監査保存失敗 | コイン回収と返金済み状態だけ残り、再試行しても監査が作成されなかった | 累積返金額・回収数・残高・監査を一括確定。既存の累積計算と重複防止を維持 |
| コンビニ払込票の監査保存失敗 | 支払い待ち状態だけ残り、再試行時は発行の監査が省略された | 払込票情報と監査を同じ注文同期の中で確定 |
| 支援への返信の監査保存失敗 | 返信は届き、返信済み扱いにもなったのにエラーを返した | メッセージ・返信済み更新・監査を一括確定し、失敗時は未返信のまま保持 |
| 遅い注文本文と年齢情報の変更 | 本文の読込み前の成人フラグを使い、確認状態の変更後も決済ページを発行できた | 本文取得後の最新状態で年齢条件を確認 |
| 決済サービス待ちの間のログアウト・BAN・年齢状態変更 | 無効になった要求へ支払い可能なURLを返した | サービス応答後にセッション・利用条件を再確認し、不許可ならURLを返さずページの終了を試みる |
| 注文確認・キャンセルの遅延応答 | ログアウト後の要求にも注文情報を返した | 外部通信完了後に認証を再確認し、失効した要求へ注文を返さない |
| 決済ページ発行の監査保存失敗 | URLを返していないのに支払い可能なページと未完了注文が残り、利用枠も占有した | 開始状態と監査を一括確定。失敗時はページの終了を試み、サービス側のIDを保持したエラー状態にする |

決済ページの後処理は、既に入金済みの注文をエラーや未払いへ戻さない。ログアウト直前に入金が確定した場合も正当なコイン付与を保持し、通知の再送で二重付与しない。外部サービスへの終了要求が失敗した場合も、その注文のサービス側IDは失わない。
