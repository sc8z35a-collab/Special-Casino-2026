# アカウント切替・通知・復元の追加監査（2026-10-30）

基点は PR #64 を取り込んだ main `8721035e5a9b8852c6ddbdad0df271700039cfea`。使い捨てアカウントと実際のクライアントコードを使い、応答の遅延、画面の閉じ直し、別アカウントへの切替、保存途中の失敗を再現した。本番アカウントや資産は検査用に変更していない。日付は日本時間。

## 修正した問題

| 問題 | 影響と修正 |
|---|---|
| 古いプロフィールで購入枠・日次報酬が巻き戻る | 残高の旧版拒否とは別に、完全なプロフィール同士の更新番号も比較する。新しい残高通知だけを受けた場合は、必要なプロフィール情報を引き続き受け入れる |
| ログアウト後も旧口座の銀行情報や完了処理が残る | 日次報酬、購入数、期限、時差、購入ルールを消去する。APIが既に完了していても、旧口座の待機中コールバックは残高・抽選結果・日次報酬を適用できない |
| 未ログインで始めたログイン・OAuthの応答が新しいログインを上書きする | 認証を返す経路にもセッション世代を適用する。不要になった成功応答のセッションは、そのトークンだけを指定して破棄する。公開情報の取得は維持する |
| 同じトークン文字列への再設定で古いパスワード応答が有効になる | パスワード変更開始時のトークンと世代の両方を確認する。別の操作へ移った場合は未使用の新セッションを破棄し、現在のログインを保持する |
| 閉じた登録・ログイン・引き継ぎ・パスワード画面が遅い応答で動く | 画面操作の世代を確認し、終了したフォームの成功・エラー・ボタン解除を無視する。放棄されたログインのセッションは破棄する。確定したパスワード変更自体は取り消さない |
| 無効な名前へ編集した後に前の名前の利用可能表示が出る | 入力直後に旧問い合わせを無効化する。通常の新規登録では引き継ぎコードと次の画面への処理が一回だけ動くことも確認する |
| 直接アカウントを切り替えると前のレベル・クエスト・画面情報が残る | サインインとサインアウトで共通の口座初期化処理を使い、クエスト、仕事、木、ガチャ、観戦、通知などへ旧口座の終了を伝える。新しい口座の残高を直ちに適用する |
| 古いプロフィールでVIP・アバター・所持品が巻き戻る | 別口座または古い完全プロフィールを拒否し、必要なら最新状態を再取得する。同じ更新番号で変わるプロフィール情報は引き続き反映する |
| ログアウト確認や通知解除の完了が別口座をログアウトさせる | 確認前の口座と世代を、確認後・通知解除後・サーバー応答後に照合する |
| 旧口座の既読処理が別口座の会話・未読表示へ作用する | 切替時に既読タイマーと入力中表示を解除し、既に送信済みの既読応答も世代で判定する |
| 通知端末の上限で現在使っている端末が消える | 再登録時に登録時刻を単調に更新し、別口座から移した端末も直近の端末として扱う |
| 端末上限の整理失敗でも通知の登録先だけ変わる | 通知登録、配信元情報、上限整理を同じトランザクションで確定する |
| 遅い404・410応答で更新済みの通知登録が消える | 配信時点の端末・口座・暗号鍵・登録版がすべて一致する場合だけ削除する。現行の失効登録は従来どおり削除する |
| 通知オフ・ログアウト後に古い登録処理が通知を再有効化する | 自動同期、許可待ち、ブラウザ登録、解除の各待機点で口座・操作・ダイアログを確認する。古い解除は別口座の購読を解除せず、通知タップの遅い応答も新口座へ画面遷移しない。ネイティブ着信の通知済み情報も口座切替時に初期化する |
| 事前の通知解除が通信失敗するとログアウト後も通知先が残る | この端末の通知先をログアウト要求へ渡し、本人の端末解除と当該セッション削除をまとめて確定する。他端末・他セッション・別口座の通知先を保持する。従来の本文なしログアウトにも対応する |
| 通知登録を含むバックアップが復元できない | 正しい暗号鍵列名 `p256dh` を列名検証が拒否していた。英小文字・数字・アンダースコアからなる正規の識別子を許可する。不正なSQL列名は拒否し、復元途中の変更もロールバックする |
