### 運営の権限を守る仕組み（自動で働くもの）

- **権限は「名前」ではなく「その名前を最初に使ったアカウント」に固定されます。** 運営（と開発者）の権限は名前に付いています（`OPERATORS`・運営サイトでの付与）。アカウントが消えたり名前が変わったりして名前が空いたとき、あとから同じ名前で登録した別の人が権限を引き継がないように、最初に権限を使ったアカウントに結びつけます。別のアカウントが同じ名前を使っていると、権限は付かず、運営ログと通知に「運営の名前を別のアカウントが使用」と出ます。結びついている名前は、新しく登録できません。持ち主が変わったとき（名前を変えた本人など）は、運営サイトで開発者コードを使って付与し直すか、管理コマンド `staff-pin <ユーザー>`（結びつけを外すのは `staff-unpin <名前>`）で直します。
- **弱いパスワードの警告**: 運営・閲覧者がログインしたとき、パスワードが 12 文字より短い・数字だけ・同じ文字ばかり、のどれかだと、プロフィールのタブに「！」と理由が出ます（ログインは止めません）。
- **開発者の追加認証を必須にする**（任意）: 設定 `REQUIRE_DEV_MFA=1` を入れると、開発者のアカウントは、プロフィールで追加認証（認証アプリ）を設定するまで、運営サイトのほかの画面を使えません。
- **運営用の API の断りを確かめるテスト**: `npm test` に、運営用のすべての API が、知らない人・ふつうのプレイヤー・ログアウト済みのログインを断ることを確かめるテストが入っています（新しい API を足して断りを忘れると、テストが落ちます）。
- **追加部品（拡張）の差し込み口**: サーバーに、ゲーム本体とは別に管理する部品を足せます（`server/ext/index.js` に並べます。このリポジトリでは空です）。部品は、自分の表（テーブル）・`/api/ops/x/` 以下の API（運営だけ・パスキー必須）・保管庫と開発者日記の画像を受け取る前後での確認・運営サイトに渡すファイル（2 分だけ有効な札つき）・アカウントメニューの項目を持てます。部品を付けて動かしたあとで、部品が外れたデプロイが走ると、**アップロードを止めて**（確認なしで通さないため）、自動点検が知らせます。意図して外したときは、管理コマンド `ext-forget <部品の名前>` で止めを解きます。仕組みと約束は `server/core/ext.js` の冒頭にあります。
- **自動点検**: サーバーが自分で、6 時間ごと（運営サイトの「サーバー」タブの「今すぐ点検」でいつでも。開発者だけ）に次を見ます。ふだんは何も送らず、異常のときだけ運営ログと Discord／LINE に出ます（異常は【危険】、お知らせは通常の通知）。
  - 運営ログの鎖がつながっているか、後ろが切り取られていないか、書き換えを止める仕組みが外されていないか（外されていれば付け直します）
  - 運営権・閲覧者の権限・追加認証・開発者コードが、運営ログに記録のないまま付いたり変わったりしていないか（点検を始める前からあったものは、そのまま受け入れます）
  - ゲームの登場人物（npc）に見せかけたアカウント、運営でも閲覧者でもない人の運営サイトのログイン
  - サーバーの設定の変化（パスキーの鍵・通知・ボットが外れた、管理用トークンが付いた、運営の名前の一覧が変わった、など。中身は保存せず、有る・無いと印だけを比べます）
- **ログの石碑（運営ログの消えない控え）**: 運営ログは、データベースの中だけにあるのではありません。**1 行ずつ、書き換えも上書きもできないファイルにして、データベースとは別の場所にも刻みます**（`server/core/stele.js`）。
  - **刻み方**: まだ刻んでいない行を、1000 行（か数 MB）ごとの「控え」にまとめます。控えは **名前のとおりに 1 回だけ作られ、あとから書き換えられません**（Cloudflare では R2 のバケット。ここ〔Node〕ではフォルダの読み取り専用ファイル）。控えは **ひとつ前の控えのハッシュを持ち**（途中の 1 つだけを抜くことはできません）、サーバーの鍵で署名され、**書いたあとに読み返して同じか確かめてから**「刻んだ」ことにします。新しい行ができて数十秒後（と、6 時間ごとの自動点検のとき）に刻みます。
  - **見張り**: 自動点検のたびに新しい控えを、**1 日 1 回はすべて**（1 回に 20 か所ずつ）読み直し、ハッシュ・署名・つながり・**データベースの行とすべての項目が同じか**を確かめます。行が 1 字でも違う・控えが消えている・後ろが切り取られている・データベースが巻き戻っている、のどれも見つかり、運営ログと Discord / LINE に出ます（点検の「異常」）。刻んだ行がデータベースで変わっているときは、その先を刻みません。
  - **戻す**: データベースの行が控えより少ない（初期化・古いバックアップへの巻き戻し・破損）とき、**足りない行を控えから自動で戻します**（いまある行から続いているときだけ。運営ログは過去には戻りません）。サーバーの鍵が替わっていて署名が合わないときは自動では戻さず、`stele restore --trust-unsigned`（開発者が内容を確かめたうえで）。
  - **証人**: 1 日に 1 回、いちばん新しい行の番号とハッシュが Discord / LINE に届きます。サーバーがすべて入れ替えられても、ここに残った値で、その時点の記録を証明できます。
  - **容量**: データベースの大きさ（Cloudflare は 1 つ 10GB まで）と運営ログの大きさを見て、70% と 90% で知らせます。運営ログは消せないので、増える一方です。
  - **書き込みに失敗したら**: 行をデータベースに書けなかったときは、その行を **まず別の記録（Node は追記専用の `ops-log.jsonl`、Cloudflare は Workers Logs）に丸ごと残して**から、その操作も失敗させます。Node では、書き込んだ行はその場で `ops-log.jsonl` にも 1 行ずつ追記します（`fsync` つき）。
  - **開発者の控え**: サーバータブの「ログを書き出す」（開発者）か、`node server/node/admin-cli.js [--remote URL] log-save ファイル` で、全部の行を 1 行 1 件のファイルに保存できます（先頭から最後までのつながりを確かめてから書き、上書きはしません）。`stele` で状態、`stele check` でいま刻んで全部確かめる、`stele restore` で戻す。
  - **R2 のバケットロック（おすすめ）**: Cloudflare では、控えは既定でゲームの保管庫のバケット（`VAULT`）の `oplog/` に入ります。**別のバケットを作って `OPLOG` という名前でつなぎ**（`wrangler.jsonc` の `r2_buckets` に追加）、さらに **[バケットロック](https://developers.cloudflare.com/r2/buckets/bucket-locks/)**（`npx wrangler r2 bucket lock add <バケット名> --name oplog --prefix oplog/ --retention-indefinite`）をかけると、Cloudflare 自身が、Worker の鍵を盗んだ人にも、控えの削除と上書きを許さなくなります。ロックの書き方は変わることがあるので、実行前に公式の説明を見てください。

`login-wait`（ログインの画面だけ）。テストと確認：`server/test/ops-traffic.test.js`（tick・差分・履歴・知らせ・一覧の「同じ」）、`server/test/ops-cache.test.js`（ハッシュの名前と Service Worker）。実ブラウザ `node tools/check_ops_traffic.cjs`（Playwright が必要）、実際の Worker `node tools/check_worker.cjs`。

始め方:

1. [Discord Developer Portal](https://discord.com/developers/applications) で New Application。「General Information」の **Application ID** と **Public Key** を控える
2. 「Bot」で Reset Token して **トークン**を控える（登録のときに 1 回使うだけ。サーバーには入れません）
3. 「OAuth2 → URL Generator」で scopes に `bot` と `applications.commands` を選び、できた URL でボットを自分の Discord サーバーに招待
4. Discord の「ユーザー設定 → 詳細設定 → 開発者モード」をオンにして、サーバーのアイコンを右クリック →「サーバー ID をコピー」。運営・開発者・閲覧者のロールの ID も、サーバー設定 → ロールで右クリックしてコピー
5. Cloudflare の Worker の「設定 → 変数とシークレット」で、シークレット `GATE_KEY`（32 文字以上のランダムな文字列）、`DISCORD_APP_PUBLIC_KEY`（Public Key）、`DISCORD_GUILD_ID`（サーバー ID）、`DISCORD_STAFF_ROLE_IDS`（ロール ID。複数はカンマ区切り）を入れて再デプロイ
6. 手元で `DISCORD_APP_ID=… DISCORD_GUILD_ID=… DISCORD_BOT_TOKEN=… node tools/discord-register.mjs` を 1 回実行（`/passkey` が登録されます）
7. Developer Portal の「General Information → Interactions Endpoint URL」に `https://（公開URL）/api/discord/interactions` を入れて保存（Discord が署名つきの確認を送り、サーバーが答えると保存できます）
8. Discord で `/passkey` と送ると、あなただけに見える形で今日のパスキーが出ます。運営サイトを開いて入力
